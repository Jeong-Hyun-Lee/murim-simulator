# 장비 UI 페이퍼돌 리디자인 + "장구"→"장비" 명칭 통일

## 배경

브레인스토밍(`wiki/synthesis/현재구현-기반-브레인스토밍-2026-09-11.md`)에서 언급된 UX 개선 요구를 사용자가 구체화: 게임 내 "장구" 명칭을 "장비"로 통일하고, 현재 좌측 슬롯 목록 + 우측 상세 2단 컬럼 구조인 `EquipPanel`을 캐릭터 중심 페이퍼돌(paper-doll) 레이아웃으로 리디자인한다.

## 1. 명칭 변경: 장구 → 장비 (전면, 코드 식별자 포함)

### 범위

- **파일명**: `src/components/panels/EquipPanel.tsx` → `GearPanel.tsx`, `src/game/equipData.ts` → `gearData.ts`
- **타입/식별자**: `EquipItem`→`GearItem`, `EquipDerivedStats`→`GearDerivedStats`, `PanelKey`의 `"equip"`→`"gear"`, state 필드 `equippedItems`→`equippedGear`
- **UI 문구**: 화면에 보이는 모든 "장구" 한글 텍스트 → "장비" (탭 버튼, 패널 제목, 주석 중 사용자 대상 문구 등)
- **유지**: `equipItem`/`unequipItem`/`enhanceItem`/`disassembleItems` 액션 함수명은 동사(장비를 장착/해제/강화하는 동작)라 명칭 선택과 무관 — 그대로 둔다. `wiki/concepts/장구-시스템.md` 등 위키 문서명은 이번 스펙 범위 밖(구현 완료 후 별도 위키 갱신 때 함께 정리).

### 세이브 호환성

`src/game/state.ts`의 `SAVE_KEY`를 `"murim-simulator-save-v1"` → `"murim-simulator-save-v2"`로 올린다. 마이그레이션 코드는 작성하지 않는다 — 새 키로 저장을 시작하면 기존 플레이어는 자동으로 초기 상태부터 다시 시작한다(사용자 확정: 세이브 데이터 초기화 허용, 현재 프로덕션 플레이어 없음). 구버전 키(`-v1`)는 브라우저 localStorage에 방치되지만 더 이상 읽지 않으므로 동작에 영향 없음.

## 2. 장비창 UX: 해부학적 페이퍼돌 레이아웃

### 컴포넌트 구조

`GearPanel.tsx`(구 `EquipPanel.tsx`) 내부를 두 영역으로 재구성:

1. **페이퍼돌 영역** (신규) — 중앙에 목현 캐릭터 이미지, 주위에 9개 장비 슬롯 박스.
2. **하단 전체 인벤토리 그리드 + 선택 분해** — 기존 그대로 유지, 변경 없음.

기존의 좌측 "슬롯 목록" 컬럼과 우측 "슬롯 상세(강화/해제/인벤토리 후보)" 컬럼 2단 구조는 제거되고, 페이퍼돌 슬롯 클릭 시 뜨는 팝오버가 그 역할을 흡수한다.

### 캐릭터 이미지

`assets/sprites/character/mokhyeon-idle-sheet.png`의 첫 프레임(0,0,256,256)을 정적 이미지로 재사용한다(신규 에셋 제작 없음, 96×96 표시 크기로 축소). 호흡 애니메이션은 이번 범위에서 제외 — 정지 프레임 1장만 사용.

### 슬롯 배치 (3열 그리드, 해부학적 대응)

```
        [머리]
[목]           [무기]
[팔]  캐릭터   [몸통]
[허리]         [반지R]
      [발][반지L]
```

9개 슬롯(`ALL_SLOTS` = weapon/body/head/arm/foot/waist/neck/ringL/ringR)을 CSS Grid로 배치. 정확한 grid-template-areas는 구현 단계에서 확정하되, 위 상대적 배치(머리 위, 목·무기 어깨 옆, 팔·몸통 중단, 허리·반지 하단, 발 최하단)를 따른다. 장착된 슬롯은 기존 `GRADE_COLOR` 테두리색 관례를 그대로 적용, 빈 슬롯은 무채색 테두리 + 슬롯명만 표시.

### 슬롯 상세 팝오버

슬롯 클릭 시 해당 슬롯 위치에 팝오버(absolute positioning, 클릭한 슬롯 기준)가 뜬다. 팝오버 내용은 기존 `EquipPanel`의 우측 상세 영역과 동일한 정보를 그대로 옮긴다:

- 장착된 아이템이 있으면: 등급·강화단계, 강화 성공확률/비용, 보호부적 체크박스(해당 시), "강화하기"/해제 버튼, 전 부족 시 "전 부족 · 사냥터로" CTA(기존 로직 그대로 재사용)
- 장착된 아이템이 없으면: "장착된 장비가 없습니다" 안내
- 해당 슬롯에 맞는 인벤토리 후보(장착 가능한 아이템) 목록 + 각각 "장착" 버튼 — 기존 `candidateItems` 로직 그대로 재사용

팝오버는 바깥 영역 클릭 또는 Esc 키로 닫힌다. 슬롯을 바꿔 클릭하면 팝오버 내용만 전환(이전 팝오버 닫고 새 팝오버 즉시 표시).

### 상태 관리

기존 `selectedSlot` state를 팝오버 표시 대상 슬롯으로 재사용(닫힘 상태는 `null`로 표현하도록 타입을 `SlotId | null`로 변경). `useProtection`, `checkedIds`(하단 분해용) state는 그대로 유지.

### 변경 없음

- 하단 "전체 인벤토리 ({count}) · 강화석 · 보호부적" 표시줄과 인벤토리 그리드, "선택 분해" 버튼 — 100% 그대로.
- `store.ts`의 `equipItem`/`unequipItem`/`enhanceItem`/`disassembleItems` 액션 로직 — 변경 없음(호출부만 팝오버 안으로 이동).
- `App.tsx`가 이미 전달 중인 `onNavigate` prop — 팝오버 안 CTA에서 그대로 사용.

## 범위 밖

- 캐릭터 이미지 애니메이션(idle 호흡 루프) — 정지 프레임으로 단순화, 추후 원하면 CSS steps() 애니메이션으로 확장 가능.
- 좁은 화면(모바일) 반응형 검증 — 이 게임은 고정 크기 캔버스(960×540) 오버레이 UI 전제, 이번 스펙에서 별도 반응형 작업 없음.
- 다른 슬롯 개수/장비 시스템 자체의 밸런스 변경 없음.

## 테스트/검증 계획

- `npx tsc --noEmit`, `npm run build` 통과 확인.
- 브라우저(claude-in-chrome)로 실제 확인: 슬롯 9개 모두 클릭 시 팝오버 표시, 팝오버 바깥 클릭 시 닫힘, 아이템 장착→강화→해제 흐름 정상 동작, 전 부족 CTA 클릭 시 사냥터 패널 전환, 하단 인벤토리 그리드/분해 기능 기존과 동일하게 동작.
- 세이브 리셋 확인: 브라우저 localStorage에서 구버전 키(`-v1`)가 남아있어도 게임이 `-v2` 키로 정상 초기 상태로 뜨는지 확인.
