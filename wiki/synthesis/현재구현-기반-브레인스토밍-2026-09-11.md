# 현재 구현 상태 기반 브레인스토밍 (기획/디자인/구현)

2026-09-11에 실제 코드(`src/`)와 위키를 대조해 뽑은 목록이며, 2026-09-18 기준으로 아직 열려 있는 항목만 남겼다. 밸런스·서사 공백은 [[기획-공백-브레인스토밍]]에서 다룬다.

## 기획

- **스토리 전개 아트**: `OnboardingFlow.tsx` 인트로는 텍스트 대사 카드 3장뿐이다. 대7 심마전·대10 엔딩 등 클라이맥스에 쓸 정지 일러스트가 없다.
- **메타 UI**: 우편함, 랭킹, 전투·획득 로그 패널이 없다. 랭킹은 서버가 필요해 [[장기-플레이-시스템]]에서도 범위 밖으로 둔다.
- **재화 부족 시 연결 흐름 부재**: 장비 강화·무공 연마에서 재화가 모자라면 버튼이 비활성될 뿐, 상점이나 기부 화면으로 잇는 흐름이 없다.

## 디자인

- **피격 이펙트**: 적이 플레이어를 때릴 때는 아직 프로시저럴 원형 확산과 붉은 플래시를 쓴다. 타격(일반·치명타) 이펙트만 이미지로 교체됐다.
- **강화 결과 연출**: 강화 성공·실패에 효과음만 있고 반짝임·흔들림 같은 화면 연출이 없다.
- **토스트 표현**: `Toast.tsx`는 `전황` 라벨 하나로 모든 알림을 같은 모양으로 보여준다. 보상·경고·해금을 구분하는 아이콘·색이 없다([[UI-Element-대체-기획서]] `frame-toast-note`, 6.1 표).
- **최초 로딩 화면**: 첫 에셋을 읽는 동안 보여줄 화면이 없다. 전투 에셋 로딩 실패 시의 재시도 안내만 있다.
- **BGM 부재**: 효과음 8종과 토글은 있으나 배경음악은 없다.

## 구현

- **`store.ts` 비대화(1,341줄)**: 전투·장비·무공·문파·기연·환골탈태·목표·수련탑 액션이 한 zustand store에 있다. 도메인별 슬라이스 분리를 검토할 시점이다.
- **`BattleCanvas.tsx`(685줄) 단일 `useEffect`**: 앱 초기화, 스프라이트 로딩, 전투 틱, 이펙트 처리가 한 이펙트 안에 있다.
- **번들 코드 스플릿 미적용**: `npm run build`가 500KB 초과 청크 경고를 낸다(pixi.js가 메인 청크에 포함).
- **자동 테스트 전무**: `package.json`에 test 스크립트가 없다. `combat.ts`처럼 순수 함수 위주 로직부터 붙이면 회귀 방지에 효과적이다.
- **세이브 스키마 버전 부재**: `loadState`가 기본값과 병합해 필드 추가는 견디지만, 필드의 뜻이 바뀌는 변경을 다룰 버전·마이그레이션 경로가 없다. 저장 백업 코드도 같은 스키마를 그대로 옮긴다([[장기-플레이-시스템]] 2절).

## 4모션 스프라이트 연동

`BattleCanvas.tsx`는 대기·공격1·공격2·사망 시트를 읽는다. 공격2와 사망은 선택 로드하고, 목현 v2는 각각 6·9·9·8프레임을 사용한다. 공격1/2는 전투마다 선택하고, 사망은 마지막 프레임에서 멈춘다.

## 다음 단계 제안

우선순위는 참고용이며 최종 판단은 사용자가 한다.

1. 피격 이펙트 이미지 교체(남은 전투 이펙트 하나)
2. 토스트 종류 구분과 최초 로딩 화면
3. `store.ts` 슬라이스 분리(다음 큰 기능 추가 전에)
4. 순수 함수부터 최소 자동 테스트 도입
