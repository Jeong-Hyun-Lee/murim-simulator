# 현재 구현 상태 기반 브레인스토밍 (기획/디자인/구현)

2026-09-11 시점 실제 코드(`src/`)와 위키를 직접 대조해 뽑은 목록. [[기획-공백-브레인스토밍]](2026-07-27)이 이미 다룬 밸런스/서사 공백은 대부분 유효하지만 이번엔 재나열하지 않고, 그 이후 실제로 구현된 코드를 기준으로 새로 보이는 격차만 정리했다. 우선순위 판단·채택 여부는 사용자 결정 사항 — 아래는 후보 목록이다.

## 기획

### 신규 추가 후보

- **캐릭터 상태 확장**: `BattleCanvas.tsx`/`sprite.ts`는 현재 `idle`/`attack` 두 상태만 존재. 피격(hurt)·기절/사망(death)·승리(victory) 포즈가 없어 전투 중 "맞았다/이겼다/졌다"는 것을 스프라이트 자체로는 전혀 표현 못 함(피격은 tint 색상 변경으로만 대체 중). 최소한 사망(패배 시 쓰러지는 포즈) 하나만 추가해도 임팩트가 큼.
- **전투력 지수 노출**: [[스테이지-레벨링-기획서]] 7장에 전투력 합산 공식이 있지만, 실제 UI(`PlayerStatus.tsx`) 어디에도 전투력 숫자가 안 보임 — 레벨/HP/EXP 바만 있음. 장구/무공/문파/환골탈태 각 출처가 전투력에 얼마나 기여하는지 보여주는 브레이크다운도 없음(→ [[기획-공백-브레인스토밍]] "스탯 상세 브레이크다운 화면 없음"이 아직도 그대로).
- **패배 리스크 재설계**: `store.ts enemyAttack()`을 보면 패배 시 HP 완전 회복 + 소액 위로 보상(EXP/Gold) + 같은 스테이지 즉시 재도전이 이미 구현돼 있음 — 사용자가 예시로 든 "보스에게 패배해도 계속 경험치를 쌓는다"는 이미 동작 중(보스/일반 몬스터 구분 없이 전부 동일 로직). 다만 지금은 사실상 "죽어도 손해가 거의 없음"이라 보스전 긴장감이 약함 — 보스만 별도로 재도전 쿨다운/약화 디버프를 주는 등 보스와 일반 몹의 패배 결과를 차등화할지는 검토 가치 있음.
- **스토리 전개 아트**: `OnboardingFlow.tsx` 인트로는 텍스트 대사 카드 3장뿐, 일러스트 없음(위키에도 "일러스트 자산 없어 축소" 명시). 대7 심마전·대10 엔딩 등 스토리 클라이맥스에 쓸 정지 일러스트가 여전히 0장.
- **메타 UI 전반**: 설정 화면, 우편함, 랭킹, 전투 로그 패널 — [[기획-공백-브레인스토밍]] 지적 그대로 코드에도 전혀 없음(재확인).

### 개선 후보

- **재화 부족 시 CTA 부재**: `EquipPanel`/`GongPanel` 등에서 강화 비용이 부족할 때 상점으로 바로 연결하는 흐름이 없음(버튼 비활성만).
- **탭 잠금 해제 안내 통일**: `TopBar.tsx`는 잠금 탭 클릭 시 토스트만 띄우는 방식으로 이미 통일돼 있음(과거 문서의 "4개 탭 방식이 제각각" 문제는 해결된 상태) — 참고로 남김.

## 디자인

### 신규 추가 후보

- **스테이지 배경 아트 부재**: 지금 전투 캔버스는 `app.init({ background: 0x242430 })` + 바닥 사각형(`0x141419`) 단색 두 장이 전부 — 배경 이미지가 실제로 하나도 없음. [[디자인-프롬프트-큐]]에 대2(흑시장) 프롬프트만 있고 정작 지금 플레이 중인 대1(혈랑채) 배경조차 없다는 게 이번에 확인된 가장 눈에 띄는 공백.
- **피격 이펙트**: 현재 피격 시 스프라이트 tint 색만 바뀌고(`ENEMY_HIT_TINT`, 플레이어는 반투명 붉은 사각형 오버레이) 파티클/스크린 셰이크/타격감 있는 별도 이펙트 없음.
- **강화 버튼 인터랙션 피드백**: `EquipPanel`/`GongPanel`에서 강화 버튼 클릭 시 수치만 즉시 바뀌고 성공/실패 연출(성공 시 반짝임, 실패 시 흔들림 등)이 없음.
- **화폐/아이템 아이콘**: `TopBar`의 전/내공/영약이 전부 텍스트 라벨뿐(`전 {gold}`), 아이콘 이미지가 하나도 없음. 영약 자체도 아이템으로서의 비주얼(약병 등)이 없음 — [[디자인-프롬프트-큐]] 신규 항목 후보.
- **토스트 팝업 디자인**: `Toast.tsx`는 plain `<div>`에 텍스트만 넣는 구조 — 카테고리(정보/경고/보상)별 색상·아이콘·등장 애니메이션 없음.
- **체력바 디자인**: `PlayerStatus`/`EnemyStatus`의 HP바가 단색 `bar-fill` div — 그라디언트, 낮은 체력 경고색, 데미지 잔상(연한 트레일) 같은 디테일 없음.

### 개선 후보

- 이미 [[디자인-프롬프트-큐]]에 대기 중인 항목(데미지 숫자 폰트, 크리티컬 히트 이펙트)은 그대로 유효 — 재중복 기재 안 함.
- 버튼 디자인 전반(hover/active/disabled 상태 구분)을 `style.css` 기준으로 한번에 점검할 필요.

## 구현

### 개선 후보

- **`BattleCanvas.tsx`(228줄) 단일 `useEffect`**: 앱 초기화, 스프라이트 로딩, 전투 틱, 이펙트 처리가 전부 한 이펙트 안에 있음. 기능이 늘수록(피격 이펙트, 배경 파츠 추가 등) 더 커질 구조라 초기화/틱 로직을 분리하는 것도 고려할 만함.
- **라이브러리 재검토**: 현재 스택(PixiJS 캔버스 + React HUD + Zustand)은 이 규모(단일 화면, 유닛 수 적음)엔 과하지도 부족하지도 않아 보임 — 지금 시점에 바꿀 필요는 낮다고 판단, 다만 배경 다중 레이어(패럴랙스)나 파티클 이펙트가 늘어나면 PixiJS 이펙트 라이브러리(`@pixi/particle-emitter` 등) 추가 검토는 유효.

### 6모션 스프라이트 연동 체크리스트 (2026-09-11 작성, 2026-09-12 혈랑채 두목 대상으로 구현 완료)

[[디자인-프롬프트-큐]]에 캐릭터 6모션(idle/공격1/공격2/피격/쓰러짐/승리, 프레임 수 확정: 6/7/7/3/6/5) 재설계 프롬프트를 등재했다. 혈랑채 두목 이미지가 먼저 확보되어 `BattleCanvas.tsx`에 아래 항목을 구현·브라우저 검증 완료. 플레이어(목현)·혈랑채 졸개·챕터2 보스들은 이미지만 확보된 상태(디자인-프롬프트-큐 참고)라 이 항목 재사용해 이어서 진행.

- **스프라이트 로딩 확장 (완료)**: `tryLoadAnimatedSprite` 헬퍼로 attack2/hurt/death/victory를 옵셔널 로드(파일 없으면 `null` 반환, `Promise.all` 전체 실패 방지) — 혈랑채 졸개처럼 아직 2모션뿐인 캐릭터도 그대로 공존.
- **공격 랜덤 스왑 (완료)**: `EnemyAnimSet.attack2` 존재 시 `Math.random() < 0.5`로 attack1/attack2 중 하나를 매 공격마다 선택.
- **피격 애니메이션 (완료)**: 플레이어 공격이 적중(비처치)하면 `playEnemyOneShot(kind, set.hurt, 'idle')`로 hurt 재생 후 자동 idle 복귀.
- **쓰러짐 애니메이션 (완료)**: 적 처치 시 `playEnemyOneShot(kind, set.death, 'hold')`로 death 재생, 마지막 프레임을 idle 복귀 없이 홀드(보스 첫 격파 시 `awaitingBossReward` 연출 동안 유지됨을 확인). 플레이어 패배 연출은 이번 범위에서 미변경(기존처럼 즉시 리트리트).
- **승리 애니메이션 (완료)**: 보스가 플레이어를 쓰러뜨렸을 때(`result.playerDefeated`)만 `set.victory` 재생 — "보스 자신의 승리" 해석(적용 대상: 보스 전용, 졸개는 victory 에셋 자체가 없음).
- **구조 (보류)**: 애니메이션 슬롯을 다루는 헬퍼(`enemySpritesOf`/`hideAllEnemySprites`/`returnToIdle`/`playEnemyOneShot`)는 추가했지만, `BattleCanvas.tsx` 단일 `useEffect` 자체를 별도 훅으로 분리하는 리팩토링은 이번 범위에서 하지 않음 — 요청 범위 밖이라 보류.
- **JSON 메타 생성 (완료)**: PIL/numpy 멀티시드 플러드필 배경제거 + 균등폭 프레임 분할 스크립트(`pack_boss6motion.py`)로 6시트 전부 생성. (scipy 미설치 환경이라 연결-성분 라벨링 대신 12점 시드 플러드필로 대체, gap 기반 프레임 분리 대신 균등폭 분할로 대체 — 소스 이미지가 알파 채널 없고 프레임 간 여백도 없었기 때문.)
