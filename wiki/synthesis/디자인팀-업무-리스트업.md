디자인팀(배경/에셋/UX 디자이너 3인, `agents/디자인팀/`)이 각자 담당 영역 기준으로 기획 문서 전체를 검토해 뽑은 디자인 업무 리스트. 아직 실제 컨셉 제작 전 단계 — "무엇을 만들어야 하는가"만 정리.

## 배경 디자이너 (장소/환경)

### 0. 선행 작업
| 업무 | 무엇을 / 왜 | 우선순위 |
|---|---|---|
| 배경 아트 스타일 가이드·팔레트 앵커 | 수묵화 톤·근경/중경/원경 레이어 표준·색감 앵커·도트 해상도 기준 선확정. 안 하면 장소 16곳(스테이지10+문파6) 개별 작업 후 톤 불일치로 재작업 | 상 |
| 메인 화면(성장보드) 배경 | 튜토리얼 최초 화면이자 상시 노출 화면, 대1 전투 배경과 레이어링 기준 공유 필요 | 상 |

| 2 | 흑시장 | 상 | 문파 탭 해금 시점과 근접 |
| 3 | 팽가장원 | 상 | 첫 비무 배경 |
| 4 | 사공 은신처 | 중 | |
| 5 | 혈교 살수 아지트 | 중 | |
| 6 | 마두 소굴 | 중 | |
| 7 | 심마·내면전 | 상 | 특수 연출 보스전+환골탈태 1회차 게이트+스토리 클라이맥스 겹침, 통상 배경과 다른 초현실 톤 필요해 조기 착수 권장 |
| 8 | 혈교 선봉기지 | 중 | |

### 2. 문파 거점 배경 (6곳)
| 문파 | 우선순위 | 비고 |
|---|---|---|
| 청운문 | 상 | 대2 클리어 시 최초 노출("내 문파" 직행), 대9 파손판 베이스 |
| 화산파/무당파/남궁세가/개방/소림사 | 중 | 가입 시점 유저 재량이라 청운문만큼 급하지 않음. 컨셉 방향(쾌검/도가/패도/정보/외공)은 스타일가이드 확정 직후 일괄 리스트업 권장 |

### 3. 특수 연출 배경
| 업무 | 우선순위 |
|---|---|
| 환골탈태 리셋 연출 배경(기운/빛 폭발) | 상 — 대7 배경과 시기 맞물려 함께 설계 |

파이프라인 연계: 근/중/원경 패럴랙스 레이어로 제시, Aseprite MCP 도트화 전제, "캔버스=배경/DOM=UI" 아키텍처 하 텍스처 아틀라스 로드 전제.

## 에셋 디자이너 (캐릭터/몬스터/아이콘/뱃지/엠블럼)

### 0. 공통 기반 (선행)
- 등급색 팔레트 → 아이콘 프레임 시각 샘플 확정 (상)
- 아이콘/스프라이트 픽셀 그리드 규격 확정 (상)
- 보스/일반몹 구분 프레임 규칙 (중)

### 1. 캐릭터
- 강진우 기본 실루엣/포즈(idle/attack) — 대1 블로커, 상
- 환골탈태 경지별 외형 변화 여부 — 기획 확인 대기, 하

### 2. 몬스터/보스 (대1→대10, 스테이지-레벨링-기획서 1.3절 매핑)
대1(혈랑채 두목)·대2(흑시장 조직 두목) = 상. 대3~6(팽가 소공자/사공 사용자/혈교 살수 두목/마두)·대7(심마, 특수 연출) = 중. 대8(혈교 선봉대장)·대9(청운문 배신자)·대10(척망, 페이즈별 형상 변화 필요) = 하(제작 순서상 후순위, 단 퀄리티 비중 높게).

### 3. 무공 아이콘 (5보드 × 노드 7개, 해금순 대1/3/5/7/9)
- 노드 계층 공통 프레임(1차/2차/캡스톤 위계) — 상, 삼재검법과 동시 진행
- 삼재검법 1보 세트 — 상
- 회선장법/유운경신술 세트 — 중
- 태을혼원공/폭뢰도법 세트 — 하

### 4. 장구 아이템 (9슬롯 × 6등급)
- 9슬롯 베이스 실루엣 + 하품/중품 배리에이션 — 상
- 상품/절품 배리에이션 — 중
- 신품/선품(발광 이펙트 포함) — 하
- 무기 슬롯-무공 계열 매칭 여부 기획 확인 필요 — 중

### 5. 환골탈태 경지 뱃지 (7단계)
후천/선천/초절정 = 중(대7·대9 게이트 대응). 화경/현경/생사경/등봉조극("N중" 공통틀)/승급 연출 스틸컷 = 하.

### 6. 문파 엠블럼 (6곳) — 전부 중
청운문 포함 6곳 모두 문파 목록 카드에 초반부터 노출되므로 동일 우선순위.

### 7. 상점/기연 기타
- 강화석/보호부적/영약/전(錢) 아이콘 — 중 (반복 사용 기초 소모품, 조기 확정 효율적)
- 기연함 + 등급별 오픈 연출 스틸컷 5종 — 하

## UX 디자이너 (디자인 시스템/톤앤매너/컴포넌트 비주얼)

현재 상태: `ux-시나리오-목업.html`(8페이지, 라이트 양피지 기본+다크는 CSS 변수로만 병기)와 `wiki/design/ux-목업-05-메인화면-다크리디자인.svg`(1페이지, 별도 하드코딩 팔레트로 그린 다크 시안)가 톤·토큰·구조 세 층위에서 서로 다른 상태 — 이 불일치 해소가 최우선.

### A. 톤앤매너 확정 (최우선, 나머지 업무 대부분이 여기 종속)
- 라이트/다크 공존 상태 해소 — 어느 쪽이 "공식 톤"인지 결정 (상)
- 두 다크 팔레트 불일치 정리 (HTML `--dark` 변수 vs 05번 SVG 하드코딩 색상, 서로 다른 값) (상)

### B. 디자인 토큰
- 공식 다크 토큰 세트 확정 및 `:root` 반영 (상)
- 등급 6단계 색상의 다크 배경 대비 검증 (값 자체는 불변, 배경/테두리 보정만) (중)
- 상태색(성공/경고/위험) 토큰화 (중)

### C. 컴포넌트 비주얼 시스템 문서화
- 디자인 시스템 단독 위키 문서 작성 (현재 명세가 HTML 소스에만 존재) (상)
- 버튼 5상태(gold/recommend/disabled/locked/max) 다크 재검증 (중)
- 아이콘 톤 통일 방침(한자 인장 vs 커스텀 스트로크 vs 이모지 배제) 수립 (중)
- 인장(seal) 모티프의 다크 HUD 반영 여부 결정 — 무협 정체성 유지 vs 장르표준 HUD 전환 (중, A와 직결)

### D. 다크 리디자인 확장 (A 결정 후 착수)
- 나머지 7페이지 다크 버전 제작 (상, A 선결)
- Figma 미완성 섹션 이어작업 (중)
- 파퍼돌/인벤토리/가챠 등 고밀도 컴포넌트 다크 대비 사전 프로토타입 검증 (하)

### E. 기타
- 웹폰트(Pretendard/Noto Serif KR/Nanum Myeongjo) self-host/서브셋 방침, 엔진 스택 담당과 조율 (하)

## 팀 간 연계 포인트

- 배경 디자이너의 "스타일 가이드" ↔ UX 디자이너의 "톤앤매너 확정(A)"이 사실상 같은 결정(무협 라이트 수묵 vs 다크 HUD) — 두 팀이 따로 정하면 안 되고 하나의 결정으로 합쳐야 함.
- 에셋 디자이너의 "등급색 팔레트 아이콘 프레임"과 UX 디자이너의 "등급 6단계 다크 대비 검증"도 같은 등급색 토큰을 다른 관점(아이콘 vs UI 배경)에서 보는 것 — 토큰 값 확정은 한 번만.
- 대7(심마) 시점에 배경(초현실 내면전)·에셋(심마 특수 비주얼)·UX(환골탈태 승급 연출)가 동시에 필요 — 세 담당이 개별 진행 시 톤 불일치 위험, 공동 스프린트 권장.
