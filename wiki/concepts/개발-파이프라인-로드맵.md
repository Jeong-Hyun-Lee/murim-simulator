# 무림인 키우기 — 개발 파이프라인 로드맵 (큰 분류)

Claude Code(터미널 AI 에이전트) 또는 Claude Desktop 앱에서 MCP 서버들을 연동해 구축하는 자동화 파이프라인. 원래 3단계였으나, 2026-07-27 브레인스토밍에서 "낡은 목업을 그대로 다음 단계로 넘기면 오류가 디자인 시스템 레벨로 고착된다"는 지적에 따라 0단계를 추가했다. 2026-07-31, Figma MCP는 UI 디자인 자체를 생성하지 못하고 다이어그램(FigJam)만 가능하다는 한계가 확인됨에 따라 Figma 단계를 제거하고, 클로드가 SVG 컨셉아트/HTML 목업을 직접 제작하는 방식으로 대체했다([[비주얼-디자인-시스템]], [[배경-아트-컨셉]], [[에셋-아트-컨셉]] 참고).

## 0. 목업 최신화 및 디자인 토큰 정의

다음 단계(클로드 디자인 제작)로 넘어가기 전에 반드시 먼저 끝낸다:

1. **목업 최신화** — `wiki/raw/assets/*.svg`, `wiki/concepts/ux-시나리오-목업.html`을 최신 위키 확정 사항(등급체계 6단계, 경지 표기 통합, 보스명 매핑 등)과 다시 대조해 어긋난 부분이 없는지 확인.
2. **디자인 토큰화** — 지금까지 각 문서에 하드코딩 값으로만 존재하는 색상(등급색 6종, 배경/테두리색 등)·타이포·스페이싱을 이름 붙은 토큰(예: `color.grade.하품`, `color.grade.선품`)으로 정리. 하드코딩 값 그대로 넘기면 이후 색상 하나 바꿀 때마다 모든 화면을 手작업으로 고쳐야 함. 2026-07-31 다크 무협 HUD 톤 확정과 함께 완료([[비주얼-디자인-시스템]]).

## 1. 클로드 디자인 제작 — SVG 컨셉아트 + HTML 목업

Figma 없이 클로드가 직접 화면/배경/캐릭터·아이템 비주얼을 제작한다. [[ux-시나리오-기획서]]에서 확정한 화면 구성(1920x1080, 상단바/좌우패널/중앙캔버스/하단바)과 각 탭(무공/장구/문파/환골탈태/상점) 레이아웃은 `ux-시나리오-목업.html`(다크 톤)로, 스테이지 배경·캐릭터/보스/아이콘 등 오브젝트 에셋은 손으로 그린 벡터 SVG 컨셉아트로 제작해 `wiki/raw/assets/`에 저장한다.

## 2. Aseprite MCP — 캐릭터/이펙트 도트 에셋 생성

Aseprite MCP로 게임에 들어갈 캐릭터와 이펙트 도트 에셋을 말로 지시하여 생성한다. [[캔버스-렌더링-기술스택-조사]]에서 정의한 스프라이트/이펙트 요구사항(타격 이펙트, 파티클, 캐릭터 idle/attack 애니메이션)과 1단계에서 확정한 SVG 컨셉아트를 참조 자산으로 삼아 실제 도트 그래픽 리소스를 이 단계에서 제작. (미연결 상태 — 연결 전까지는 1단계 SVG 컨셉아트가 임시 산출물 역할)

## 3. Claude Code — 웹 게임 엔진 코딩 및 에셋 결합

클로드에게 웹 게임 엔진(Pixi.js, Phaser, 혹은 Unity) 코딩을 시켜 1·2단계 에셋들을 하나의 2D 웹 게임으로 결합한다. 엔진 선택은 [[캔버스-렌더링-기술스택-조사]]의 기존 결론(PixiJS 전투 캔버스 + React/Vue DOM 하이브리드 추천)과 맞춰 검토하되, 이 로드맵 원본은 Pixi.js/Phaser/Unity 세 후보를 열어둔 상태로 제시됨 — 최종 엔진 확정은 별도 의사결정 필요.

## 다음 결정 필요 사항

- Aseprite MCP 연결 시점, 연결 전까지 SVG 컨셉아트로 어디까지 진행할지
- Aseprite 에셋의 아트 스타일 가이드(도트 해상도, 팔레트, 캐릭터 사이즈 기준) 사전 정의 필요 — 픽셀 그리드 규격은 [[에셋-아트-컨셉]]에서 1차 확정됨
- 최종 게임 엔진 확정 (Pixi.js 기존 추천 vs Phaser vs Unity)
