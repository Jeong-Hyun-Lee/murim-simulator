# 무림인 키우기 — 개발 파이프라인 로드맵 (큰 분류)

Claude Code(터미널 AI 에이전트) 또는 Claude Desktop 앱에서 MCP 서버들을 연동해 구축하는 자동화 파이프라인. 원래 3단계였으나, 2026-07-27 브레인스토밍에서 "낡은 목업을 그대로 다음 단계로 넘기면 오류가 디자인 시스템 레벨로 고착된다"는 지적에 따라 0단계를 추가했다. 2026-07-31, Figma MCP는 UI 디자인 자체를 생성하지 못하고 다이어그램(FigJam)만 가능하다는 한계가 확인됨에 따라 Figma 단계를 제거하고, 클로드가 SVG 컨셉아트/HTML 목업을 직접 제작하는 방식으로 대체했다.

## 0. 목업 최신화 및 디자인 토큰 정의

다음 단계(클로드 디자인 제작)로 넘어가기 전에 반드시 먼저 끝낸다:

1. **디자인 토큰화** — 지금까지 각 문서에 하드코딩 값으로만 존재하는 색상(등급색 6종, 배경/테두리색 등)·타이포·스페이싱을 이름 붙은 토큰(예: `color.grade.하품`, `color.grade.선품`)으로 정리. 하드코딩 값 그대로 넘기면 이후 색상 하나 바꿀 때마다 모든 화면을 手작업으로 고쳐야 함. 2026-07-31 다크 무협 HUD 톤 확정과 함께 완료.

## 1. 클로드 디자인 제작 — SVG 컨셉아트 + HTML 목업

Figma 없이 클로드가 직접 화면/배경/캐릭터·아이템 비주얼을 제작한다. 확정한 화면 구성(1920x1080, 상단바/좌우패널/중앙캔버스/하단바)과 각 탭(무공/장구/문파/환골탈태/상점) 레이아웃은 HTML 목업으로, 스테이지 배경·캐릭터/보스/아이콘 등 오브젝트 에셋은 손으로 그린 벡터 SVG 컨셉아트로 제작해 `wiki/raw/assets/`에 저장한다.

## 2. 캐릭터 스프라이트 — 페인터리 레퍼런스 크롭

캐릭터 idle/attack 스프라이트는 더 이상 Aseprite로 도트 트레이싱하지 않는다. 레퍼런스 원화(사용자 제공 또는 외부 이미지 생성 AI 산출물)에서 프레임 좌표를 자동 검출해 크롭·리사이즈만 한 뒤 페인터리 색감 그대로 스프라이트시트(PNG+JSON)로 저장한다.


## 3. Claude Code — 웹 게임 엔진 코딩 및 에셋 결합

클로드에게 웹 게임 엔진(Pixi.js, Phaser, 혹은 Unity) 코딩을 시켜 1·2단계 에셋들을 하나의 2D 웹 게임으로 결합한다. 엔진 선택은 [[캔버스-렌더링-기술스택-조사]]의 기존 결론(PixiJS 전투 캔버스 + React/Vue DOM 하이브리드 추천)과 맞춰 검토하되, 이 로드맵 원본은 Pixi.js/Phaser/Unity 세 후보를 열어둔 상태로 제시됨 — 최종 엔진 확정은 별도 의사결정 필요.
