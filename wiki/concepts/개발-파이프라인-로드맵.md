# 무림인 키우기 — 개발 파이프라인 로드맵 (큰 분류)

Claude Code(터미널 AI 에이전트) 또는 Claude Desktop 앱에서 MCP 서버들을 연동해 구축하는 자동화 파이프라인. 3단계로 구성.

## 1. Figma MCP — UI/메뉴 레이아웃 학습

Figma MCP로 웹 게임의 UI 및 메뉴 레이아웃 정보를 클로드에게 학습시킨다. [[ux-시나리오-기획서]]에서 확정한 화면 구성(1920x1080, 상단바/좌우패널/중앙캔버스/하단바)과 각 탭(무공/장구/문파/환골탈태/상점) 레이아웃을 Figma로 옮겨 디자인 소스로 삼고, Figma MCP를 통해 클로드가 실제 좌표/컴포넌트 구조를 읽어 구현에 활용.

## 2. Aseprite MCP — 캐릭터/이펙트 도트 에셋 생성

Aseprite MCP로 게임에 들어갈 캐릭터와 이펙트 도트 에셋을 말로 지시하여 생성한다. [[캔버스-렌더링-기술스택-조사]]에서 정의한 스프라이트/이펙트 요구사항(타격 이펙트, 파티클, 캐릭터 idle/attack 애니메이션)에 대응하는 실제 도트 그래픽 리소스를 이 단계에서 제작.

## 3. Claude Code — 웹 게임 엔진 코딩 및 에셋 결합

클로드에게 웹 게임 엔진(Pixi.js, Phaser, 혹은 Unity) 코딩을 시켜 1·2단계 에셋들을 하나의 2D 웹 게임으로 결합한다. 엔진 선택은 [[캔버스-렌더링-기술스택-조사]]의 기존 결론(PixiJS 전투 캔버스 + React/Vue DOM 하이브리드 추천)과 맞춰 검토하되, 이 로드맵 원본은 Pixi.js/Phaser/Unity 세 후보를 열어둔 상태로 제시됨 — 최종 엔진 확정은 별도 의사결정 필요.

## 다음 결정 필요 사항

- Figma 디자인 소스 파일을 언제/누가 만들지 (기존 SVG 목업을 Figma로 옮길지, 처음부터 Figma에서 재설계할지)
- Aseprite 에셋의 아트 스타일 가이드(도트 해상도, 팔레트, 캐릭터 사이즈 기준) 사전 정의 필요
- 최종 게임 엔진 확정 (Pixi.js 기존 추천 vs Phaser vs Unity)
