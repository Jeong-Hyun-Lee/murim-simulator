# 모바일 UX 개선 기획서

## 1. 방향과 범위

사용자 확정 방향: **세로형·하단 탭 중심**. P0 범위는 게임에 구현됐다(12절 구현 현황). 모바일 웹을 우선하고 PC에서도 같은 탐색 구조를 사용한다. 네이티브 앱 출시·설치 기능은 별도 범위다.

목표는 짧게 접속해 현재 진행을 이해하고, 성장 수단을 선택한 뒤, 전투에서 효과를 확인하는 흐름이다. 전투 감상과 성장 조작을 각각 충분한 크기로 제공한다. 시스템별 비용·확률·보상·해금 조건은 기존 판정을 사용한다.

아트·밸런스·세이브 구조는 이 기획으로 바꾸지 않는다. 기존 시스템 문서의 수치와 서사는 해당 문서가 기준이며, 화면 배치는 이 문서가 기준이다. 2절 진단은 가로 960×540 구현 당시 기준이다.

## 2. 현재 구현 진단

실제 화면 실측 대신 2026-09-13 코드와 위키를 대조한 결과다. 사용성 문제는 구조에서 도출한 가설이며 기기 검증은 구현 단계에서 진행한다.

| 현재 근거 | 모바일에서 예상되는 문제 | 개선 방향 |
|---|---|---|
| `src/App.tsx`: 960×540 전체에 동일 배율 적용 | 390px 너비에서 약 0.406배로 UI까지 축소 | 화면 너비에 맞춰 DOM을 재배치하고 전투만 독립 렌더링 |
| `TopBar.tsx`: 재화·7개 패널·정지·효과음 집중 | 작은 버튼과 높은 탐색 부담 | 하단 4탭, 화면별 재화, 상황별 행동 분리 |
| `GongPanel.tsx`: 좌측 보드 목록과 긴 노드 행 | 보드 이름·비용·행동이 좁은 폭에서 경쟁 | 보드 선택기와 세로 노드 카드 |
| `GearPanel.tsx`: 페이퍼돌과 슬롯 팝오버 | 화면 끝 상세가 잘리거나 캐릭터를 가릴 위험 | 캐릭터 영역, 소지품 목록, 중앙 비교 팝업 |
| `BossDialog.tsx`: 전역 덮개와 단일 진행 버튼 | 성장 중 보스 조우가 작업을 가로막음 | 전투 대기 상태를 유지하며 준비 화면 진입 허용 |
| `useHoldRepeat.ts`: 누른 즉시 실행·200ms 후 반복 | 스크롤 시작과 연속 소비가 겹칠 위험 | 탭은 1회 확정, 길게 누르기는 지연 후 반복하고 손가락 이동·스크롤 시 취소 |
| `store.ts`: 문파 기부 시 가용 내공/영약 전체 소비 | 단순 기부 버튼으로 소비량을 오인 | 전량 기부 문구와 실행 전 합계 확인 |
| `claimDailyBonusIfNeeded`: 날짜별 정액 지급 | 방치 시간 비례 보상으로 오인 가능 | ‘오늘의 접속 보너스’, 자동 지급 내역만 안내 |

## 4. 정보 구조와 진입점

| 하단 탭 | 첫 화면 | 하위 화면·주요 행동 |
|---|---|---|
| 무공 (기본 화면) | 상단 고정 전투 영역 + 하단 스크롤 무공 목록 | 무대 위 사냥터 선택, 보스 도전/보상 팝업, 보드 선택, 연마 |
| 장비 | 캐릭터·9슬롯·소지품 | 장착 비교, 강화, 최적 장착, 분해 |
| 문파 | 청운문·문파 성장·기여도 | 내공/영약 전량 기부, 삼재검법 2보 바로가기 |
| 상점 | 일반상점/기연 | 전으로 영약 교환, 1회/10회 뽑기, 확률·결과 |

공통 상단의 초상 버튼은 ‘내 정보’를 열어 스탯·경지·환골탈태를 보여준다. 우상단 설정 버튼은 모든 탭에서 열리며, 설정창에서 전투 일시정지/재개와 효과음 켜기/끄기를 조작한다. 환골탈태 가능 시 전투 상단 상태 버튼에서도 상세 팝업을 연다. 상점은 기존대로 대1 보스 클리어 후, 문파는 대2 클리어 후, 장비는 최초 아이템 획득 후 활성화한다. 환골탈태 진입은 대7 클리어 조건을 사용하고 실행 조건은 현재 회차 판정을 따른다.

잠긴 탭도 자리를 유지하고 이름·자물쇠를 표시한다. 탭하면 조건 설명 화면을 열며 현재 진행과 필요한 조건을 함께 보여준다. 미구현 문파 채팅·토벌전·실결제 상품·퀘스트는 탭이나 빈 배너로 추가하지 않는다.

탭 전환 시 보드·소지품 필터·목록 스크롤 위치를 세션 동안 보존한다. 환골탈태 등으로 선택 항목이 유효하지 않으면 유효한 첫 항목으로 이동한다. 다른 탭에서 바로가기로 들어간 하위 화면은 ‘뒤로’로 출발 화면과 선택 상태를 복원한다.

## 5. 공통 화면 틀

- 기본 설계 폭 390 CSS px, 검수 폭 280/320/360/390/412/430px. 수치는 프로젝트 설계 목표이며 특정 플랫폼 규격을 인용한 값이 아니다.
- 앱 전체를 확대·축소하지 않는다. 기본 본문 16px, 보조 정보 14px, 주요 터치 영역 최소 48×48px, 인접 행동 간격 최소 8px를 목표로 한다.
- 상단은 도호·경지와 현재 화면에 필요한 재화 1~2종을 우선 표시한다. 재화 상세에서 정확한 전체 수치를 확인한다. 축약 숫자는 만/억 단위를 통일하며 구매 버튼에는 실제 비용을 표시한다.
- 하단 탭 높이 64px에 기기 안전 영역을 더한다. 주요 연마·장착처럼 화면 맥락에서 즉시 필요한 행동만 본문에 두고, 사냥터 선택·보상·비교/확인은 중앙 팝업으로 연다.
- 무공 탭에서는 전투 영역을 고정하고 그 아래 목록만 세로 스크롤한다. 장비·문파·상점은 각 본문을 스크롤한다. 가로 스크롤·핀치 확대를 기본 탐색으로 요구하지 않는다. 긴 목록과 키보드가 떠 있는 상태에서는 조작 버튼까지 스크롤 가능해야 한다.
- 넓은 화면은 최대 480px의 같은 세로 UI를 중앙에 배치하는 1차안을 사용한다. 가로 회전도 허용하며 높이가 짧으면 본문을 스크롤한다. 별도 PC 다열 UI는 후속 검토다.
- 먹색 바탕·따뜻한 종이색 카드·금색 주요 행동을 사용한다. 등급색은 기존 6단계를 유지하고 이름을 함께 표기한다. SD 페인터리 캐릭터가 가장 눈에 띄도록 장식 테두리는 절제한다.

## 6. 전투와 상태 전환

무공 메인은 상태 버튼·적 체력·전투 무대·내 체력을 상단에 고정하고, 그 아래 무공 목록만 스크롤한다. 390px 폭의 전투 무대는 논리 크기 640×390으로 낮추며 실제 캐릭터 공격 범위를 확인해 조정한다. 기존 16:9 화면을 중앙에서 잘라 맞추지 않는다. 전투 영역 비율에 맞게 인물 간격과 배경을 재구성하되, 주인공 왼쪽/오른쪽 응시·적 오른쪽/왼쪽 응시 및 공통 프레임·모션 배율 규칙을 지킨다. [[캐릭터-이미지-생성-지침]] 참고.

장비·문파·상점에는 높이 약 44px의 전투 요약줄을 둔다. 현재 스테이지와 ‘자동 전투 중/반복 사냥 중/보스 도전 대기/보상 확인 대기/일시정지’를 텍스트로 보여주고 탭하면 무공 메인으로 이동한다. 작은 전투 캔버스를 중복 생성하지 않는다.

| 상황 | 표시와 행동 | 진행 규칙 |
|---|---|---|
| 일반 등반 | 현재 스테이지와 실행 상태, 우상단 설정 진입 | 다른 탭에서도 전투 계속 |
| 반복 사냥 | 상단에 사냥 중 위치와 원래 등반 위치 표시, 전투 무대의 사냥터 버튼 옆 ‘등반’ 버튼과 사냥터 팝업 안 ‘등반 위치로 복귀’ | 복귀 위치를 임의로 바꾸지 않음 |
| 보스 조우 | 아직 클리어하지 않은 보스에 도달하면 어느 탭에서든 도전 팝업을 바로 띄움: ‘도전’·‘수련하기’ | 도전 확인까지 정지. 수련하기·닫기는 직전 스테이지 반복 사냥으로 전환하고, ‘등반’으로 돌아오면 팝업을 다시 띄움. 이미 클리어한 보스는 팝업 없이 바로 전투 |
| 보스 격파 | 격파 즉시 어느 탭에서든 결과 팝업을 띄움 | 기존 지급 시점 유지, ‘계속하기’ 또는 닫기로 보상 수령·진행 재개 |
| 패배 | 후퇴한 위치와 무공/장비 진입점 | 기존 후퇴·재전투 판정 사용, 자동으로 사냥 모드로 바꾸지 않음 |
| 수동 정지 | 화면에 ‘일시정지’ 표시, 설정창에 ‘전투 재개’ | 탭 전환·설정창 닫기로 재개하지 않음 |

보스 도전·격파는 팝업이 바로 뜨므로 상단 상태 버튼은 ‘환골탈태 가능’만 둔다. 일반 성장은 전투 아래 무공 목록이나 장비 탭에서 바로 진입하므로 전투 하단에 별도 카드나 바로가기를 쌓지 않는다. 전투력만으로 보스 승리 가능성을 보장하거나 근거 없는 ‘추천 전투력’을 제시하지 않는다.

탭 전환은 전투 실행 생명주기를 바꾸지 않아야 한다. 현재 전투 진행이 `BattleCanvas`의 틱에 연결되어 있으므로 탭을 바꾸며 캔버스를 제거하면 진행이 멈출 위험이 있다. 구현 첫 단계에서 단일 전투 실행 주체를 유지하도록 분리하거나 계속 유지되는 구조를 검증한다. 화면 밖 렌더링을 줄여도 전투 계산을 중복하거나 중단하지 않는다. 브라우저가 백그라운드에 있는 동안의 시간 비례 진행은 이번 UX에서 보장하지 않는다.

사냥터는 무공 메인 전투 무대 위에 절대 배치한 상단 중앙 스테이지 버튼에서 **중앙 팝업**으로 연다. 대스테이지는 팝업 안의 세로 목록으로, 선택한 대스테이지의 소스테이지는 각 행의 이름·클리어 여부·선택 표시로 제공한다. 현재 사냥 위치와 등반 복귀 위치를 팝업 상단에 표시하고, 반복 사냥 중 ‘등반 복귀’도 이 안에 둔다. 행 선택만으로 이동하지 않고 팝업 안 ‘선택한 곳에서 사냥’으로 적용한다. 아직 클리어하지 않은 곳은 이유를 표시하며 실행 가능 여부는 기존 `startFarming` 판정을 사용한다. 닫으면 선택을 적용하지 않는다. `combat.ts`의 전투 진행 데이터는 대30까지 있지만 배경·적 그림은 대1 자산을 공유하므로, 대11~30을 숨길지 여부는 아트 적용 범위와 별도로 결정한다.

## 7. 성장 화면 상세

### 무공

상단 보드 선택기를 누르면 7개 보드를 세로 목록으로 보여준다. 보드별 재화·진행률·잠금 사유를 표시한다. 노드는 1차/2차/오의 순으로 세로 카드에 배치하고 선행 조건은 ‘제1식 천 Lv.10 필요’처럼 실명으로 보여준다. 효과 설명은 실제 적용 스탯에서 가져오고 향후 기획상의 광역 공격 등은 현재 효과로 표시하지 않는다.

카드에 현재 레벨, 다음 효과, 1회 비용, 최대 10회 실제 합계와 횟수를 표시한다. 대성 직전 3회만 가능하면 ‘3회 연마’로 표시한다. ‘1회 연마’는 짧게 누르면 1회, 길게 누르면 연속 연마한다. 스크롤과 겹치지 않도록 누른 즉시 실행하지 않고 0.4초 뒤 반복을 시작하며, 손가락이 움직이거나 스크롤이 시작되면 반복하지 않는다. 재화가 부족해지거나 대성에 도달하면 즉시 멈춘다.

### 장비

9슬롯 페이퍼돌은 유지하되 슬롯 이름과 선택 표시를 제공한다. 슬롯을 누르면 중앙 팝업에서 현재 장비와 후보 장비를 위아래로 비교한다. 내용이 길면 팝업 안에서 스크롤하며 인접 슬롯 위로 작은 팝오버를 띄우지 않는다.

소지품은 기본 2열 카드, 큰 글자 설정에서는 1열로 바꾼다. 슬롯 필터·등급/강화 단계 정렬·빈 상태 안내를 제공한다. 비교에는 등급·강화 단계·변경 스탯을 표시한다. ‘최적 장착’은 현재 게임의 선정 기준을 설명하고 모든 보조 스탯에서 우월하다고 표현하지 않는다.

강화 영역에는 성공 확률, 실패 시 결과, 전/강화석 비용, 보호부적 사용 여부를 한 묶음으로 보여준다. 분해는 선택 모드에 진입해 대상 개수와 반환 강화석을 확인한 뒤 실행한다. 장착 중 장비를 분해 대상에 포함하지 않는다. 실패와 성공은 글자·아이콘·수치로 함께 알리고 색이나 효과음에만 의존하지 않는다.

### 문파

청운문 소개, 문파 레벨/특전, 사용 가능 기여도, 누적 기여도 순으로 보여준다. 두 기여도를 서로 다른 의미로 설명한다. ‘내공 전량 기부’와 ‘영약 전량 기부’는 실제 소비량·획득 기여도·기부 후 잔액을 확인하는 시트를 연다. 내공은 교환 단위에 못 미치는 잔액이 남을 수 있으므로 ‘보유 내공 전부 소멸’로 안내하지 않는다. 수량 지정 기부는 별도 기능 변경이므로 이번 기본안에 포함하지 않는다.

‘문파 무공 보기’는 무공 탭의 삼재검법 2보로 연결한다. 해금은 실제 삼재합일 대성 판정으로 안내하며 임의의 문파 Lv.15 조건을 붙이지 않는다.

### 상점·기연

일반상점/기연을 상단 2개 소탭으로 제공한다. 일반상점은 현재 구현된 영약 교환을 표시하고 다음 1개 비용·보유 전·구매 후 잔액을 보여준다. 기연은 영약 잔액, 천장 진행, 1회/10회 비용, 확률 정보 진입점을 한 화면에서 찾을 수 있게 한다. 확률은 현재 데이터 표에서 표시한다.

결과는 2열 카드와 획득 요약으로 구성한다. ‘닫기’와 비용이 명시된 ‘다시 뽑기’를 분리하고 연출 중 연타를 막는다. 뽑기 자체의 지급은 한 번만 실행하며 연출 스킵·탭 전환·결과 재열람이 재지급을 일으키지 않는다. 현재 결과가 재진입 시 초기화되므로 세션 내 미확인 결과를 보존하는 UX 변경이 필요하다. 앱 재시작 뒤 결과 재열람은 저장 정책을 추가하는 후속 범위다.

### 내 정보·환골탈태

내 정보에 전투력·주요 능력치·보조 능력치·성장별 기여도를 단계적으로 펼친다. 전투력은 종합 참고 지수로 설명한다. 효과음과 전투 진행은 공통 상단 설정창에서 조작한다. 설정창을 닫아도 정지 상태는 유지되고, 재개 버튼을 눌러야 전투가 다시 진행된다.

환골탈태는 전용 상세 화면으로 연다. 현재/다음 경지·실제 영구 버프, 초기화 항목, 유지 항목을 세로로 나눈다. 마지막 확인에는 ‘환골탈태 실행’과 ‘취소’를 명확히 표시한다. 확인 뒤 결과 요약을 보여주고 1-1 전투로 돌아간다. 중복 탭으로 횟수가 여러 번 증가하지 않아야 한다.

코드 대조 시 `performRebirth`는 레벨·경험치·내공·무공 레벨·현재 스테이지·사냥 상태를 초기화하지만 `highestMajorCleared`는 유지한다. [[환골탈태-시스템]]의 진행도 초기화·보드 유지 서술과 정확히 일치하지 않으므로 구현 착수 전 필드별 초기화표를 확정해야 한다. 본 기획은 이 차이를 임의로 수정하지 않는다. 대15/20/25/30 게이트와 전투 진행 데이터는 대30까지 있으나, 목표 안내는 실제 플레이 가능 상태를 검증한 뒤 표시한다.

## 8. 핵심 사용자 흐름

1. **첫 접속:** 인트로 3장 또는 건너뛰기 → 도호 입력(기본 목현) → 무공 메인에서 전투 시작 → 제1식 천 첫 연마 → 변화 요약 → 같은 화면 위쪽 전투 확인. 현재 첫 성장 강제 안내는 유지하고 다른 튜토리얼을 겹치지 않는다. 재화가 부족해도 영구적으로 진행이 막히지 않는지 검증한다.
2. **짧은 재접속:** 자동 지급된 오늘의 접속 보너스 확인 → 무공 메인 상단에서 전투/대기 상태 파악 → 무공 또는 장비 성장 → 전투 확인. 시간 비례 ‘오프라인 보상 수령’ 버튼을 만들지 않는다.
3. **보스에 막힘:** 보스 대기 또는 패배 확인 → 성장 준비 → 연마/장비 교체 → 필요 시 사냥터 선택 → 등반 복귀 → 도전. 각 단계에서 현재 전투 모드가 보인다.
4. **장비 획득:** 비차단 획득 안내 → 장비 탭 → 현재 장비 비교 → 장착 → 스탯 변화 확인. 일반 드랍마다 모달을 띄우지 않는다.
5. **환골탈태:** 가능 안내 → 손실/유지/획득 비교 → 실행 확인 → 결과 → 1-1 전투. 취소 시 원래 상태로 돌아간다.

## 9. 팝업·피드백·접근성

- 주요 화면은 탭, 사냥터 선택·비교·설정·보스 결과·소비 확인은 중앙 팝업, 긴 설명은 전체 상세로 구분한다. 팝업 위에 팝업을 계속 쌓지 않고 닫거나 상세 화면으로 전환한다.
- 브라우저 뒤로는 확인창 닫기 → 시트 닫기 → 하위 화면에서 출발 화면 복귀 순으로 처리한다. 취소나 바깥 영역 탭은 소비를 실행하지 않는다. 탭 최상위에서는 브라우저 기본 이탈을 허용한다.
- 일반 보상·강화 결과는 짧은 알림으로 표시한다. 새 해금은 해당 탭 배지로 알리고 열람 후 지운다. 단순히 돈이 있다는 이유만으로 빨간 점을 계속 켜지 않는다.
- 보스 이벤트가 강화/뽑기 확인창을 덮지 않게 한다. 상태는 즉시 요약줄에 반영하고, 사용자의 현재 조작이 끝난 뒤 전투에서 확인하도록 한다.
- 버튼은 실제 버튼 요소와 명확한 이름을 사용한다. 키보드로 탐색·실행·닫기가 가능하고 시트를 닫으면 호출 버튼으로 초점을 돌려준다. 화면 읽기 도구에 전투 매 타격을 계속 읽히지 않고 보스 대기·중요 결과만 전달한다.
- 글자 확대 200%, 화면 움직임 줄이기, 효과음 끄기를 지원하는 방향으로 검수한다. 데미지 숫자보다 메뉴와 체력·현재 상태의 가독성을 우선한다.
- 로딩 실패 시 전투 영역에 재시도와 현재 상태를 표시한다. 저장 실패는 저장되지 않았음을 알리고 성공한 것처럼 숨기지 않는다. 이 실패 UI는 실제 오류 감지 연결이 필요한 구현 항목이다.

사용성 검증 목표: 신규 플레이어가 첫 성장 안내 후 같은 화면의 전투 상태를 확인하고, 기존 플레이어가 무공·장비·문파·상점을 하단 탭 1회로 찾는다. 아이템 비교 후 장착은 해당 목록에서 2회 이내 조작을 목표로 한다. 대표 사용자 5명에게 첫 연마·장착·사냥/등반 복귀·기연 비용 확인을 요청해 각 과제 4명 이상 완료를 초기 통과선으로 사용한다. 이 숫자는 목표이며 측정 결과가 아니다.

## 11. 기획 정합성과 후속 결정

동의점: 작은 화면에서 성장 조작을 읽을 수 있어야 하며, 전투 진행은 화면 탐색과 독립적이어야 한다. 기존 재화와 해금 규칙을 재사용한다.

상충점과 판단: 무공 메인에서는 낮춘 전투 영역을 고정하고 무공 목록만 스크롤해 성장 공간을 확보한다. 장비·문파·상점에서는 요약줄을 채택한다. 보스 확인은 유지하되 성장 준비를 허용한다. 짧은 조작은 빠르게 실행하되 전량 기부·분해·환골탈태는 합계를 검토할 기회를 둔다.

남은 결정 항목은 환골탈태의 필드별 초기화 규칙과 대11~20 목표 안내의 아트 적용 범위다. 세로형·하단 4탭과 무공 메인 전투 배치는 확정이며, 요약줄·시트 상세는 이 기획의 검토 대상이다.

## 12. 구현 현황 (2026-09-13)

P0 범위를 코드에 반영했다. 390/320px 세로, 844×390 가로에서 가로 넘침 없음, 탭 20회 왕복 후 캔버스 1개·전투 진행 유지, 환골탈태 확인 중복 탭 시 1회만 증가를 브라우저로 확인했다. 4탭 개편 뒤 320×568에서 전투 영역 아래 무공 목록 높이 약 112px를 확보하고 목록만 스크롤되는 것도 확인했다.

- 앱 틀: `App.tsx`가 최대 480px 세로 틀·하단 4탭·상세 화면 스택·시트를 관리한다. 무공 메인 상단에 단일 전투 화면을 유지하고 아래 무공 목록만 별도 스크롤한다. 모든 탭 화면을 계속 마운트하고 `hidden`으로 전환해 전투 틱과 화면 상태(보드 선택·필터·뽑기 결과)를 유지한다. 탭별 스크롤 위치는 전환 시 저장·복원한다.
- 공통: `AppChrome.tsx`(상단 도호·경지·탭별 재화 2종·설정, 전투 요약줄, 하단 탭, 설정/재화 상세/잠긴 탭 팝업), `Sheet.tsx`(네이티브 `<dialog>` 중앙 팝업 — Esc·바깥 탭 닫기와 초점 복귀), `common.ts`(만/억 축약, 전투 상태 문구, 탭 잠금 조건).
- 전투: `BattleTab.tsx`. 논리 캔버스 640×390에 인물 간격 340을 유지하고 배경은 높이 기준으로 맞춘다. 사냥터 선택 버튼은 무대 그림 위 상단 중앙에 겹쳐 배치하고 `StagePicker.tsx` 중앙 팝업을 연다. 보스 도전·보상·환골탈태는 상단 상태 버튼에서 중앙 팝업으로 연다. 반복 사냥 복귀도 사냥터 팝업 안에 둔다.
- 무공: 보드 선택기·세로 노드 카드·1회/최대 10회 연마, ‘1회 연마’ 길게 누르기 연속 연마(`hooks/useHoldRepeat.ts`).
- 장비: 페이퍼돌 + 슬롯 필터·정렬이 있는 소지품 목록 + 슬롯 비교 시트(현재 장비 강화 묶음, 후보별 스탯 변화·장착). 분해는 선택 모드 → 확인 시트.
- 문파: 레벨·두 기여도 구분·전량 기부 확인 시트, 2보 잠금 시 해금 조건 표시. 상점: 일반상점/기연 소탭, 확률 시트, 결과 요약·닫기·다시 뽑기, 연출 중 연타 잠금.
- 내 정보(`MyInfoView.tsx`)·환골탈태(`RebirthView.tsx`): 초기화/유지 항목은 `performRebirth` 실제 필드 기준으로 표시한다.

P1도 반영했다.

- 브라우저 뒤로: `hooks/useBackLayer.ts`가 확인창·시트·상세 화면·돌아가기 바마다 history 항목 하나를 유지하고 뒤로 가면 가장 위 레이어만 닫는다. 화면 버튼·Esc로 닫으면 남은 항목을 정리하며, 탭 최상위에서는 브라우저 기본 이탈을 허용한다.
- 새 해금 배지: 세션 중 장비·문파·상점 탭이 열리거나 무공 보드가 새로 열리면 해당 탭에 배지를 켜고, 그 탭을 열면 지운다. 접속 시점에 이미 열려 있던 것은 알리지 않는다.
- 오류 안내: 전투 에셋 로딩이 실패하면 전투 영역에 멈춤 사실과 ‘다시 시도’를 보여준다. 저장(localStorage)이 실패하면 상단에 경고와 ‘다시 저장’을 띄우고, 성공하면 지운다. 저장소가 차단돼도 효과음 설정 읽기로 앱이 멈추지 않는다.
- 접근성: 상세 화면을 닫으면 연 버튼으로 초점을 돌려준다. 글자 크기를 rem으로 바꿔 기본 글자 크기 설정을 따르며, 390px에서 글자 200% 확대 시 가로 넘침이 없음을 확인했다.

해상도·기기 호환도 반영했다.

- 단위: CSS 크기는 rem(루트 글자 크기 기준)으로 잡아 기기 글자 크기 설정을 따른다. 1~3px 선 두께와 iOS 입력창 자동 확대 기준(16px)만 px로 남긴다.
- 해상도 구간: 360px 이하 여백 축소, 300px 안팎(갤럭시 폴드 접힌 화면) 탭·헤더 축소와 카드 버튼 세로 쌓기, 가로 회전 등 높이 32em 이하에서 전투 무대를 화면 높이 45%로 제한하고 틀을 얇게, 태블릿 이상은 480px 기둥 중앙 배치. 280/320/360/390/412/430px 세로, 667×375 가로, 768×1024에서 가로 넘침 없음·하단 탭 노출을 브라우저로 확인했다.
- iOS·안드로이드: 동적 뷰포트 높이(dvh)와 미지원 기기용 실제 높이 변수 폴백, 좌우·상하 안전 영역, 두 번 탭 확대·페이지 튕김·당겨서 새로고침 방지, 입력창 자동 확대 방지, 긴 숫자의 전화번호 링크화 방지, 키보드 표시 시 화면 축소(`interactive-widget`), 홈 화면 실행 메타. `<dialog>` 미지원(iOS 15.4 미만)·`webkitAudioContext` 폴백, 전투 캔버스 위에서도 스크롤 가능, 캔버스 렌더 배율 최대 2배. 빌드 대상은 iOS 14 Safari·크롬 87 이상으로 명시했다.

미구현: 앱 재시작 후 뽑기 결과 재열람(저장 정책 추가 필요), 넓은 화면 전용 배치(P2). 기존 판정을 그대로 써서 보스 도전 대기 중에는 사냥터 이동이 막히고, 자동 등반 중 패배하면 여전히 반복 사냥 모드로 전환된다.
