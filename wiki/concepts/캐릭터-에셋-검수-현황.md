# 캐릭터 에셋 검수 현황

[[캐릭터-이미지-생성-지침]]의 실행용 체크 목록이다. 아래 공통 체크리스트는 앞으로 생성하는 주인공·적 모든 캐릭터에 적용한다. 생성 후보, PixiJS 규격으로 패킹한 최종 에셋, 게임 적용 검수를 구분한다.

## 1. 이미지 생성 후 공통 검토 체크리스트

새 원화나 모션 프레임을 생성한 직후에는 아래 순서대로 검토한다. 하나라도 통과하지 못하면 해당 결과는 후보로만 보관하고, 최종 시트에 넣지 않는다.

| 단계 | 반드시 확인할 사항 | 통과 기준 |
|---|---|---|
| 기준 대조 | 승인된 대기 이미지와 약 2.5등신 SD 비율, 의상·무기·색, 응시 방향, 모션 순서 | 주인공은 오른쪽 응시·왼쪽 루트, 적은 왼쪽 응시·오른쪽 루트. 모든 모션의 외형 기준이 하나다. |
| 원화 품질 | 전신·발·무기·공격 궤적의 완전한 표시, 포즈별 신체 배율, 프레임 간 손과 무기 연결 | 잘린 사지·이웃 포즈 조각·프레임별 자동 확대가 없다. 공격은 준비→정점→회복, 사망은 무기와 자세가 연속된다. |
| 프레임 고유성 | 프레임별 역할, 몸통·관절·무기 끝점·무게 중심·옷자락 변화, 인접 프레임 중복 | 접속용 시작·종료 외의 모든 프레임이 다른 동작이다. 인접 프레임은 최소 두 동작 요소가 다르고 실제 게임 배율에서도 구분된다. |
| 투명화 | 실제 RGBA 알파, 체크 무늬·흰색·검은색 배경 픽셀, 가장자리 잔상, 흰 의상·칼날 손실 | 투명 영역의 알파가 0이며, 어두운색·밝은색·유채색 합성에서 배경 잔상·구멍·테두리가 없다. |
| 패킹·PixiJS 규격 | 공통 셀 크기, 루트/지면 기준, 32px 안전 여백, 캐릭터당 텍스처 PNG 1장·JSON 1개(4096px 이하), PixiJS `Spritesheet` 파싱·`animations`·`anchor`·duration | 한 캐릭터의 모든 모션이 같은 셀·루트를 쓰며, 공격 범위와 쓰러짐도 셀 안에 완전히 들어간다. `Assets.load`로 파싱되고 4개 모션·프레임 수·캐릭터별 승인 공통 `sourceSize`가 지침 3.3과 일치한다. |
| GIF 검수 | 정상 속도·2배 저속의 대기 루프, 공격·사망 연결, 발과 몸통의 순간 이동 | 정지하거나 같은 포즈가 두 번 재생되는 구간이 없고 발 기준선·신체 배율·무기 길이가 튀지 않는다. 사망 마지막 프레임은 홀드한다. |
| 게임 적용 | 실제 로더의 앵커, 화면 표시 배율, 무대 바닥선, 상태 전환, 모바일 안전 영역 | 전투 화면에서 잘림·겹침·로딩 실패가 없고, 대기·공격·사망 전환이 의도한 위치에서 재생된다. |

### 결과 분류

- **생성 후보:** 원화 품질 또는 투명화 검토 전 결과. 원본 파일은 보관하지만 게임에는 연결하지 않는다.
- **패킹·PixiJS 변환 검수 통과:** 실제 알파·공통 셀·루트·여백·GIF 연결과 PixiJS 규격 파싱을 통과한 PNG와 JSON. 게임 적용 전까지는 대기 중인 최종 에셋이다.
- **게임 적용 검수 통과:** 로더·상태 전환·모바일 화면 검수까지 통과한 에셋. 해당 캐릭터의 런타임 에셋으로 사용한다.

## 2. 목현 v10 에셋 제작 현황

현재 저장소에는 전투용 v10 원본·검수본·런타임 PNG/JSON과 장비 화면에서 실제 사용하는 정적 페이퍼돌만 유지한다. 이전 전투 버전의 시트·후보·GIF·재생성 출력은 런타임과 문서에서 참조하지 않으며 제거한다.

| 항목 | 상태 | 근거 |
|---|---|---|
| 외형 기준 | 완료 | 청록·아이보리 무복, 흑발 상투와 청록 끈, 은색 직검의 2.5등신 SD 페인터리 외형을 전 모션에서 유지했다. 주인공의 루트는 왼쪽이고 모두 오른쪽을 응시한다. |
| 네 상태 프레임 | 완료 | 대기 12프레임, 공격1 16프레임, 공격2 16프레임, 사망 10프레임으로 총 54프레임이다. death는 기존 중간 스트립을 제거하고 마지막 엎어진 스트립을 새 9~10번으로 사용했다. |
| 투명 PNG | 완료 | `output/sprite-regeneration/mokhyeon-v10/*-part*.png`와 최종 시트는 실제 RGBA다. 새 이미지를 생성하지 않고 `death-part3`을 제거한 뒤 기존 `death-part4`를 새 `death-part3`으로 변경했다. |
| 공통 셀·기준점 | 완료 | 모든 프레임은 768×768px 공통 셀, `(200, 642)` 지면 기준, anchor `(0.2604167, 0.8359375)`로 복원한다. 공통 패킹 배율 `0.975238`과 런타임 배율 `0.5`를 사용하고 모션별 zoom·width·height 변경은 없다. 32px 안전 여백을 넘으면 패킹을 실패시킨다. |
| idle 흔들림 | 완료 | 12프레임의 몸통 중심 x 범위를 보정 전 10.9px에서 1px로 줄였고 지면 범위는 1px이다. 프레임별 정수 평행 이동값은 `verification.json`의 `motionFrameOffsets.idle`, 보정 전·후 수치와 공격 기준은 `verificationNotes`에 기록했다. 확대·축소나 동적 피벗 재계산은 없다. |
| 전 프레임 배율 | 완료 | v8에서 놓친 원화 카메라 차이를 전 프레임 기준으로 다시 검사했다. v8 얼굴 폭은 idle 138~142px에 비해 attack1 9~12번 86~99px, attack2 9~12번 74~91px였다. v9 attack1은 125·127·123·129px로 복원했고, attack2 9번은 얼굴 가림을 별도 기록한 뒤 머리·어깨·몸통을 함께 대조했다. |
| death 배율·바닥선 | 완료 | death 첫 프레임 원화 높이는 447px이며 공통 배율 `0.975238`을 그대로 사용한다. 남긴 10프레임의 패킹 최하단은 모두 y=650이고 마지막 9·10번은 엎어진 착지·홀드 자세다. |
| 패킹·PixiJS 변환 | 완료 | `assets/sprites/character/mokhyeon-v10-sheet.png`(4087×3156) 및 대응 hash JSON 1개로 다시 패킹했다. 4개 `animations`, 54개 프레임, 공통 768px `sourceSize`, 공통 anchor, duration 합계(960·720·720·1080ms)를 자동 검사했다. |
| GIF 검수본 | 완료 | 모션별 정상 속도와 2배 저속 GIF, 16열×4행 셀 검수본을 `output/sprite-regeneration/mokhyeon-v10/`에 다시 생성했다. death 행은 10프레임이며 접지점 y=650을 유지한다. |
| 런타임 연결 | 완료 | `BattleCanvas`를 `mokhyeon-v10`으로 전환했다. `localhost:5000`에서 v10 JSON·PNG 응답 200과 실제 전투 캔버스 로딩을 확인했다. 현재 세이브의 전투에서는 플레이어가 피해를 받지 않아 실제 패배 트리거는 재현하지 못했으며, death 상태 전환 자체는 정렬 시트·정상/저속 GIF와 JSON 복원값으로 검수했다. |

v2의 복제형 중간 프레임·가짜 체크무늬 투명도, v4의 독립 생성·프레임별 확대·자동 피벗·조용한 잘림, v5의 모션별 배율, 같은 숫자 배율만 적용한 중간 시도의 원본 크기 불일치, v8 idle 내부 이동과 공격 타격 스트립의 카메라 축소를 놓친 오판까지 원인·수치·재발 방지 규칙을 [[캐릭터-이미지-생성-지침]] 6.6~6.7에 통합 기록했다.

## 3. 혈랑채 두목 v3 에셋 제작 현황

| 항목 | 상태 | 근거 |
|---|---|---|
| 외형·방향 기준 | 완료 | 승인 후보의 흑발 상투·붉은 목도리·백색 모피·흑적색 찰갑·늑대 장식·대도를 전 모션에서 유지했다. 약 2.5등신 SD이며 화면 오른쪽에서 왼쪽을 보고, 좌우 반전하지 않는다. |
| 네 상태 프레임 | 완료 | 전체 모션 마스터 보드에서 경계 자세를 먼저 정한 뒤 대기 12·공격1 16·공격2 16·쓰러짐 10의 54프레임을 4프레임 연속 스트립으로 제작했다. 공격1은 대각 내려베기, 공격2는 낮은 수평 휩쓸기로 구분하고 두 공격의 첫·끝을 대기 경계 자세와 연결했다. |
| 공통 셀·배율·접지 | 완료 | 큰 대도의 전 공격 합집합을 모션별 축소 없이 수용하도록 전 모션 공통 셀을 896×896px로 확정했다. 공통 배율 `0.93`, 오른쪽 루트 `(624,770)`, anchor `(0.6964286,0.859375)`를 사용하며 프레임별·모션별 확대는 없다. 서기·무릎·손·몸통의 실제 지지 알파를 같은 y=770으로 평행 이동해 쓰러짐까지 바닥선을 유지한다. |
| 패킹·검수본 | 완료 | `assets/sprites/character/hyeollangchae-boss-v3-sheet.png`(4091×3122)와 대응 hash JSON 1개로 패킹했다. 4개 animation·54프레임·duration 합계 960·720·720·1080ms, 32px 안전 여백, 정상/저속 GIF, 16열×4행 정렬 시트, 소스 해시를 `verification.json`에 기록했다. |
| 런타임 연결 | 완료 | `BattleCanvas`의 두목만 통합 시트 로더로 전환하고 런타임 표시 배율을 `0.58` 한 값으로 고정했다. 쓰러짐 1080ms가 끝까지 보이도록 전투 재개 대기를 1180ms로 조정했다. `localhost:5000`의 1-10 보스 화면에서 왼쪽 응시·목현과의 체급·공통 바닥선·쓰러짐 최종 홀드와 콘솔 오류 0건을 확인했다. 현재 저장 상태의 목현이 두목을 한 번에 처치해 적 공격의 실제 발동은 정상/저속 GIF와 정렬 시트로 검수했다. |
