# 캐릭터 에셋 검수 현황

[[캐릭터-이미지-생성-지침]]의 실행용 체크 목록이다. 아래 공통 체크리스트는 앞으로 생성하는 주인공·적 모든 캐릭터에 적용한다. 생성 후보, PixiJS 규격으로 패킹한 최종 에셋, 게임 적용 검수를 구분한다.

## 1. 이미지 생성 후 공통 검토 체크리스트

새 원화나 모션 프레임을 생성한 직후에는 아래 순서대로 검토한다. 하나라도 통과하지 못하면 해당 결과는 후보로만 보관하고, 최종 시트에 넣지 않는다.

| 단계 | 반드시 확인할 사항 | 통과 기준 |
|---|---|---|
| 기준 대조 | 승인된 대기 이미지와 약 2.5등신 SD 비율, 의상·무기·색, 응시 방향, 모션 순서 | 주인공은 오른쪽 응시·왼쪽 루트, 적은 왼쪽 응시·오른쪽 루트. 모든 모션의 외형 기준이 하나다. |
| 원화 품질 | 전신·발·무기·공격 궤적의 완전한 표시, 포즈별 신체 배율, 프레임 간 손과 무기 연결 | 잘린 사지·이웃 포즈 조각·프레임별 자동 확대가 없다. 공격은 준비→정점→회복, 사망은 무기와 자세가 연속된다. |
| 프레임 고유성 | 프레임별 역할, 몸통·관절·무기 끝점·무게 중심·옷자락 변화, 인접 프레임 중복 | 접속용 시작·종료 외의 모든 프레임이 다른 동작이다. 인접 프레임은 최소 두 동작 요소가 다르고 실제 게임 배율에서도 구분된다. |
| 투명화 | 실제 RGBA 알파, 체크 무늬·흰색·검은색 배경 픽셀, 가장자리 잔상, 흰 의상·칼날 손실 | 투명 영역의 알파가 0이며, 어두운색·밝은색·유채색 합성에서 배경 잔상·구멍·테두리가 없다. |
| 패킹·PixiJS 규격 | 공통 셀 크기, 루트/지면 기준, 32px 안전 여백, 캐릭터당 텍스처 PNG 1장·JSON 1개(4096px 이하), PixiJS `Spritesheet` 파싱·`animations`·`anchor`·duration | 한 캐릭터의 모든 모션이 같은 셀·루트를 쓰며, 공격 범위와 쓰러짐도 셀 안에 완전히 들어간다. `Assets.load`로 파싱되고 4개 모션·프레임 수·768px `orig`가 지침 3.3과 일치한다. |
| GIF 검수 | 정상 속도·2배 저속의 대기 루프, 공격·사망 연결, 발과 몸통의 순간 이동 | 정지하거나 같은 포즈가 두 번 재생되는 구간이 없고 발 기준선·신체 배율·무기 길이가 튀지 않는다. 사망 마지막 프레임은 홀드한다. |
| 게임 적용 | 실제 로더의 앵커, 화면 표시 배율, 무대 바닥선, 상태 전환, 모바일 안전 영역 | 전투 화면에서 잘림·겹침·로딩 실패가 없고, 대기·공격·사망 전환이 의도한 위치에서 재생된다. |

### 결과 분류

- **생성 후보:** 원화 품질 또는 투명화 검토 전 결과. 원본 파일은 보관하지만 게임에는 연결하지 않는다.
- **패킹·PixiJS 변환 검수 통과:** 실제 알파·공통 셀·루트·여백·GIF 연결과 PixiJS 규격 파싱을 통과한 PNG와 JSON. 게임 적용 전까지는 대기 중인 최종 에셋이다.
- **게임 적용 검수 통과:** 로더·상태 전환·모바일 화면 검수까지 통과한 에셋. 해당 캐릭터의 런타임 에셋으로 사용한다.

## 2. 목현 v3 에셋 제작 현황

| 항목 | 상태 | 근거 |
|---|---|---|
| 외형 기준 | 완료 | 청록·아이보리 무복, 흑발 상투와 청록 끈, 은색 직검의 2.5등신 SD 페인터리 외형을 전 모션에서 유지했다. 주인공의 루트는 왼쪽이고 모두 오른쪽을 응시한다. |
| 네 상태 프레임 | 완료 | 대기 12프레임, 공격1 16프레임, 공격2 16프레임, 사망 14프레임으로 총 58프레임을 새로 제작했다. 원본 모션 스트립은 `wiki/raw/assets/mokhyeon-v3-*-strip-candidate.png`에 보관한다. |
| 투명 PNG | 완료 | 원본 및 최종 시트는 RGBA이며, 최종 시트의 투명 영역 알파가 0인 것을 검사했다. |
| 공통 셀·기준점 | 완료 | 모든 프레임은 768×768px 공통 셀, `(192, 624)` 지면 기준, anchor `(0.25, 0.8125)`로 복원한다. 전체 모션의 최대 높이에서 계산한 단일 배율을 적용해 프레임별 자동 확대를 하지 않았다. |
| 패킹·PixiJS 변환 | 완료 | `assets/sprites/character/mokhyeon-v3-sheet.png`(3991×1011) 및 대응 hash JSON 1개로 패킹했다. 4개 `animations`, 58개 프레임, 공통 `sourceSize`, 아틀라스 경계값을 자동 검사했다. |
| GIF 검수본 | 완료 | 모션별 정상 속도와 2배 저속 GIF를 `output/sprite-regeneration/mokhyeon-v3/`에 생성했다. 16열×4행 셀 검수본도 함께 제공한다. |
| 런타임 연결 | 진행 전 | 신규 시트는 게임 코드에 아직 연결하지 않았다. 로더·전투 상태 전환·모바일 무대 검수는 적용 작업에서 진행한다. |

## 3. 남은 검수와 제작 범위

| 항목 | 상태 | 다음 작업 |
|---|---|---|
| 목현의 실제 화면 상태 전환 | 진행 전 | v3 시트를 로더에 연결한 뒤 320·360·390·430px 폭에서 공격1·공격2·사망을 각각 재생해 바닥선, 공격 범위, HUD 겹침을 확인한다. |
| 대1 적 4종 신규 제작 | 진행 중 | 혈랑채 두목·졸병·정예산적 대기 후보는 각각 1254×1254px RGBA(color type 6)다. 정예산적 v3는 실제 알파 0 픽셀과 최소 33px 안전 여백을 확인했으며, 세 후보 모두 왼쪽 응시·오른쪽 루트·왼쪽 무기 공간을 유지한다. 궁수 후보와 4종의 모션·공통 셀·런타임 검수가 남아 있다. |
| 목현/적 나란히 스타일 검수 | 진행 전 | 대1 적 기준 원화가 생긴 뒤 목현과 2.5등신 비율, 선·명암·채색 밀도, 전투 크기를 한 화면에서 비교한다. |
| 대1 아트 완료 판정 | 진행 전 | 목현과 적 4종의 모바일 실측 및 모든 런타임 전환을 통과한 뒤 완료로 변경한다. |
