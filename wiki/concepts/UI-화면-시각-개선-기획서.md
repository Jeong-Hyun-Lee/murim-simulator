# UI 화면 시각 개선 기획서

## 1. 목적과 범위

2026-09-21 `localhost:5000` 실제 화면에서 무공·장비·일반상점·기연·설정·보스 팝업을 검수한 결과를 바탕으로, UI Element 적용 뒤 남은 **가독성·정보 위계·공간 배분 문제**를 정리한다. 화면 구조와 기능 판정은 [[모바일-UX-개선-기획서]], 표면 에셋 규격은 [[UI-Element-대체-기획서]]를 유지한다.

이번 범위는 다음 일곱 항목이다.

1. 기본·보조·비활성 버튼 상태 구분
2. 장비 페이퍼돌에서 캐릭터와 슬롯의 비율 조정
3. 일반상점·기연 화면의 빈 공간과 정보 밀도 조정
4. 무공 메인에서 전투·상태·무공 영역의 시각적 경쟁 완화
5. 공통 장식 프레임의 강조 단계 정리
6. 하단 탭과 상단 헤더의 가독성 개선
7. 설정·보스 등 중앙 팝업의 여백과 구분 장식 축소

적 캐릭터 출력과 전황 알림의 레이어·겹침 문제는 이 문서의 범위에 포함하지 않는다. 신규 기능, 밸런스, 재화 판정, 전투 로직, 새 UI 에셋 제작도 다루지 않는다.

## 2. 공통 개선 원칙

### 2.1 행동 상태 체계

같은 버튼 에셋을 쓰더라도 상태가 한눈에 구분돼야 한다. 색만 바꾸지 않고 표면 밝기, 테두리, 글자색, 눌림 변화를 함께 사용한다.

| 상태      | 표면과 테두리                                 | 글자                | 동작 피드백                                            |
| --------- | --------------------------------------------- | ------------------- | ------------------------------------------------------ |
| 주요 행동 | 밝은 황금·한지 표면, 금색 테두리              | 진한 먹색, 굵게     | 누를 때 1~2px 내려가고 밝기 감소                       |
| 보조 행동 | 회흑 또는 짙은 목재 표면, 얇은 금·회색 테두리 | 밝은 한지색         | 누를 때 표면만 밝아지고 테두리 유지                    |
| 이동·연결 | 녹청 표면                                     | 밝은 한지색         | 화살표·이동 아이콘 유지                                |
| 위험 행동 | 붉은 벽돌 표면                                | 밝은 한지색         | 확인 단계 전까지 주요 행동보다 강하게 빛내지 않음      |
| 비활성    | 채도와 대비를 함께 낮춘 표면                  | 읽을 수 있는 회갈색 | 눌림·광택·그림자 제거, `cursor`와 `aria-disabled` 일치 |
| 선택됨    | 남색 표면과 금색 외곽선                       | 밝은 금·한지색      | 선택되지 않은 항목보다 테두리와 글자 대비가 명확함     |

- 한 행동 묶음에서 주요 행동은 원칙적으로 하나만 둔다.
- 보조 버튼을 검은 바탕만으로 표현해 비활성처럼 보이게 하지 않는다.
- 비활성 버튼의 문구와 비용은 사라지지 않아야 하며, 활성 버튼과의 차이는 3초 안에 구분할 수 있어야 한다.
- `:hover`만으로 상태를 설명하지 않는다. 모바일에서는 기본·누름·비활성만으로 의미가 완결돼야 한다.

### 2.2 장식 강조 단계

화면의 모든 박스가 같은 무게의 금속·목재 프레임을 사용하지 않도록 세 단계로 나눈다.

| 단계  | 대상                                       | 표현                                         |
| ----- | ------------------------------------------ | -------------------------------------------- |
| 1단계 | 현재 선택, 주요 행동, 팝업 제목            | 금색 모서리·남색/황금 표면 등 가장 강한 장식 |
| 2단계 | 화면의 대표 카드, 장비 페이퍼돌, 상품 카드 | 얇은 목재·한지 프레임, 모서리 장식 최소화    |
| 3단계 | 수치 행, 설명, 구분선, 보조 상태           | 배경 명도 차와 먹 붓선만 사용                |

한 화면에 1단계 장식은 동시에 두 곳을 넘기지 않는다. 동적 텍스트가 놓이는 중앙 면에는 문양·광택·축 장식을 겹치지 않는다. 트리밍된 UI 에셋을 기존 고정 높이에 다시 늘여 쓰면서 장식이 두꺼워지지 않도록 표시 비율도 함께 재조정한다.

## 3. 화면별 개선안

### 3.1 무공 메인

현재 전황 줄, 적 상태, 전투 무대, 목현 상태, 무공 보드 선택기가 각각 독립된 강한 프레임을 사용한다. 기능은 그대로 두고 인접 요소를 한 덩어리로 읽히게 만든다.

- 적 이름·체력과 목현 이름·체력은 전투 무대의 상·하단 HUD로 인식되도록 프레임 두께와 바깥 여백을 줄인다.
- 사냥터·등반 조작은 전투 무대 내부 상단 중앙에 유지하되 캐릭터와 겹치지 않는 작은 상태 칩으로 제한한다.
- 전투 무대와 무공 영역 사이에는 굵은 별도 프레임 대신 8~12px의 한지 여백과 얇은 먹 구분선을 사용한다.
- 무공 보드 선택기는 제목·재화·완성도를 한 줄 또는 두 줄로 정리하고, 두루마리 축이 텍스트 영역을 침범하지 않게 한다.
- 390×844에서 첫 무공 카드의 제목·효과와 최소 한 개의 연마 버튼이 하단 탭 위에 보여야 한다.

적용 중심: `BattleTab.tsx`, `GongPanel.tsx`, `.battle-tab`, `.unit-status`, `.battle-stage-frame`, `.board-picker-btn`, `.gong-scroll`.

### 3.2 장비

페이퍼돌의 목적은 슬롯 수를 보여주는 것이 아니라 **현재 캐릭터와 착용 결과를 확인**하게 하는 것이다.

- 390px 폭에서 장비 캐릭터의 보이는 신체 높이를 페이퍼돌 내부 높이의 50~65%로 키운다.
- 9개 슬롯은 캐릭터 실루엣을 가리지 않으며, 슬롯 이름과 장착 상태가 두 줄 안에서 읽히게 한다.
- 빈 슬롯은 장식과 그림자를 약하게 하고, 장착 슬롯·현재 선택 슬롯만 등급 프레임과 선택 테두리를 강하게 쓴다.
- 페이퍼돌 전체 높이는 첫 소지품 행 또는 소지품 제목이 하단 고정 행동 영역 위에 보이는 범위로 줄인다.
- `최적 장착`과 `분해 선택` 설명은 버튼 위 한 줄 도움말로 유지하되 버튼과 같은 강조도를 갖지 않게 한다.
- 전투용 목현 스프라이트의 크기·기준점을 변경하지 않고 장비 화면 전용 이미지와 CSS 표시 크기만 조정한다.

적용 중심: `GearPanel.tsx`, `#gear-doll`, `.gear-doll-char`, `.gear-doll-slot`, 장비 하단 행동 영역.

### 3.3 일반상점·기연

상품 카드 아래의 넓은 빈 회벽이 화면을 미완성처럼 보이게 한다. 새 상품이나 기능을 만들지 않고 현재 정보의 배치를 재조정한다.

- 일반상점 상품 카드는 설명, 가격 요약, 교환 버튼을 세로 리듬 12~16px로 묶고 화면 상단에서 과도하게 뜨지 않게 한다.
- 약방 간판형 장식은 상품명 뒤에 겹치지 않게 제목 영역의 독립 표식으로 쓴다.
- 기연 카드는 보유 영약, 천장, 1회/10회 비용을 한 묶음으로 유지하고 확률 정보는 독립된 보조 버튼으로 보이게 한다.
- 재화 부족으로 비활성화된 뽑기 버튼도 횟수와 비용은 읽혀야 한다.
- 내용이 짧은 상태에서는 대표 카드를 화면 상단 1/3에 고정하지 말고 본문 가용 영역 안에서 시각적으로 중앙에 가깝게 배치한다. 단, 하단 탭과 겹치지 않는다.
- 카드가 세로로 늘어날 때 장식 문양을 반복하거나 빈 설명을 추가하지 않는다.

적용 중심: `ShopPanel.tsx`, `.shop-product-card`, `.gacha-pull-card`, `.gacha-pull-head`, `.gacha-pity-progress`.

### 3.4 상단 헤더

- 도호·경지는 한 묶음, 화면별 재화는 다른 묶음으로 보이게 간격과 구분선을 조정한다.
- 축약 재화 수치는 같은 기준선에 맞추고 재화명보다 숫자의 대비를 한 단계 높인다.
- 설정 버튼은 원형 장식을 유지하되 헤더 높이를 키우지 않는다.
- 320px 폭에서도 도호, 경지, 재화 2종, 설정 버튼이 서로 겹치거나 12px 미만으로 축소되지 않아야 한다.

적용 중심: `AppChrome.tsx`, `#app-header`, `.header-profile`, `.header-currencies`, `.currency-chip`, `.header-icon-btn`.

### 3.5 하단 탭

- 비활성 탭의 글자와 아이콘도 형태를 즉시 식별할 수 있게 밝기를 높인다.
- 활성 탭은 남색 면·금색 외곽선·밝은 글자로만 강조하고, 다른 탭은 장식을 줄인다.
- 잠긴 탭은 비활성 탭보다 흐리게 하되 이름과 자물쇠는 읽을 수 있어야 한다.
- 네 탭의 아이콘 광학 크기와 글자 기준선을 통일한다.
- 320~430px 폭에서 각 탭의 터치 영역은 최소 48px 높이를 유지한다.

적용 중심: `AppChrome.tsx`, `#tab-bar`, `.tab-btn`, `.tab-btn-active`, `.tab-btn-locked`.

### 3.6 중앙 팝업

- 제목 현판 바로 아래의 빈 띠를 줄이고 본문 첫 요소와 12~16px 간격으로 연결한다.
- 설정의 전투·효과음·저장 백업 구역 사이 장식은 두꺼운 프레임 대신 얇은 먹 구분선 또는 3단계 장식으로 낮춘다.
- 닫기 버튼은 제목 현판 안에 유지하며 제목과 겹치지 않는 최소 44×44px 조작 영역을 확보한다.
- 팝업의 기본·보조 버튼은 2.1의 상태 체계를 그대로 적용한다.
- 320×568에서는 팝업 외곽틀이 화면 안에 남고 본문만 스크롤돼야 하며, 390×844에서는 설정 백업 입력과 복원 버튼까지 한 번의 내부 스크롤로 도달해야 한다.

적용 중심: `Sheet.tsx`, `SettingsSheet`, 보스 도전·보상 카드, `dialog.sheet`, `.sheet-header`, `.sheet-body`, `.setting-row`.

## 4. 구현 순서

1. **상태 토큰 정리:** `.btn`, `.btn-primary`, 위험·이동·비활성·선택 상태와 글자색을 먼저 정리한다.
2. **공통 크롬 조정:** 헤더, 하단 탭, 팝업 제목·본문 여백을 수정한다.
3. **장비 비율 조정:** 페이퍼돌 캐릭터와 슬롯 크기·위치를 함께 조정하고 첫 소지품 노출을 확인한다.
4. **상점 밀도 조정:** 일반상점과 기연의 짧은 상태·재화 부족 상태를 각각 확인한다.
5. **무공 화면 위계 조정:** 전투 HUD와 무공 보드 선택기의 장식 강도를 낮추고 첫 연마 행동 노출을 확인한다.
6. **전체 화면 회귀 검수:** 공통 스타일 변경이 문파·수련 목표·수련탑·내 정보·환골탈태에 미치는 영향을 확인한다.

새 UI 에셋은 만들지 않고 `assets/ui/`의 현재 에셋을 재사용한다. TSX 변경은 상태별 클래스가 부족하거나 화면별 레이아웃을 구분할 수 없을 때만 추가하며, 우선 적용 파일은 `src/style.css`다.

## 5. 완료 기준

- 320×568, 390×844, 430×932에서 가로 스크롤과 주요 텍스트 잘림이 없다.
- 활성·보조·비활성 버튼을 색맹 모의 없이도 표면·테두리·글자 대비만으로 구분할 수 있다.
- 장비 화면에서 캐릭터가 슬롯보다 먼저 인식되고 9개 슬롯의 이름·상태도 모두 읽힌다.
- 일반상점·기연의 대표 카드가 상단에 몰리거나 하단에 과도한 빈 공간을 남기지 않는다.
- 무공 화면에서 전투 무대가 가장 먼저 보이고, 장식 프레임이 캐릭터·체력·연마 행동보다 강하게 보이지 않는다.
- 비활성 하단 탭과 보조 버튼의 문구가 배경에 묻히지 않는다.
- 설정·보스 팝업에서 제목 아래 불필요한 띠 공간과 과도한 구역 프레임이 제거된다.
- 키보드만으로 탭·버튼·팝업 닫기에 접근할 수 있고 포커스 표시가 장식 이미지에 묻히지 않는다.
- `npm run lint`, `npm run format`, `npm run build`가 통과한다.
- 실제 브라우저에서 기본·잠김·재화 부족·팝업·짧은 화면 높이 상태를 캡처 비교한다.

## 6. 구현 결과

2026-09-22 공통 스타일과 화면별 밀도 조정을 `src/style.css`에 반영했다.

- 주요·보조·비활성·선택 버튼의 표면 밝기, 글자 대비, 그림자와 누름 상태를 분리했다.
- 상단 재화 묶음의 수치 기준선과 설정 조작 영역을 정리하고, 하단 탭의 활성·비활성·잠김 상태 대비를 높였다.
- 장비 페이퍼돌의 캐릭터 표시 비율을 키우고 슬롯 높이·간격을 줄여 캐릭터와 9개 슬롯을 함께 읽을 수 있게 했다.
- 일반상점·기연의 대표 카드를 본문 가용 영역 중앙에 가깝게 배치하고 재화 부족 버튼의 횟수·비용 가독성을 유지했다.
- 전투 HUD·무공 보드 선택기·대표 카드의 프레임 두께와 바깥 여백을 줄여 콘텐츠보다 장식이 먼저 보이지 않게 했다.
- 설정 등 중앙 팝업의 제목 아래 여백과 외곽 프레임 폭을 줄이고, 설정 구역은 두꺼운 반복 프레임 대신 얇은 구분선으로 정리했다.

인앱 브라우저에서 320×568, 375×812, 430×932와 기본 데스크톱 뷰를 확인했다. 최소 폭에서 가로 잘림 없이 팝업 외곽이 유지되고 본문이 내부 스크롤되며, 375px 장비 화면에서 캐릭터·9개 슬롯·소지품 제목이 식별되고 430px 기연 화면에서 카드와 하단 탭이 겹치지 않는 것을 확인했다. 콘솔 오류는 없었다. 실제 Safari/Chrome 기기 전수 검수는 [[모바일-디자인-진행-현황]]의 별도 진행 항목으로 유지한다.
