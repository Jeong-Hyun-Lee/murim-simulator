# 캐릭터 이미지 생성 지침

향후 모든 캐릭터 이미지 생성 후 공통 검토와 목현 v2의 통과·미통과 현황은 [[캐릭터-에셋-검수-현황]]에서 관리한다.

## 1. 목적과 적용 범위

캐릭터 모션을 바꿔도 크기와 위치가 튀지 않고, 고정 좌표로 잘라 재생할 수 있는 게임용 PNG를 만든다. 주인공과 모든 적의 신규 생성·재생성·배경 제거·시트 패킹에 적용한다. 배경 풍경이나 UI에는 적용하지 않는다.

캐릭터 시트의 크기·간격·투명도·검수에 관한 과거 지침과 충돌하면 이 문서를 적용한다. 새 규격은 제작 목표이며 기존 파일의 규격이나 게임 적용 상태를 소급 변경하지 않는다.

## 2. 생성 전에 고정할 항목

- 캐릭터별 승인된 대기 포즈를 외형 기준 이미지로 정하고 모든 모션에 같은 기준을 사용한다. 얼굴·머리 크기·몸통 비율·의상·색·무기 길이를 기록한다.
- 주인공과 적을 **같은 2.5등신 SD 비율과 같은 귀여운 페인터리 그림체**로 생성한다. 머리부터 발끝까지의 키가 머리 높이의 약 2.5배가 되도록 하고, 적도 5등신 이상의 성인 체형·작은 머리·사실적인 장신 비율로 만들지 않는다. 화면상의 크기 차이가 필요하면 캐릭터 전체를 같은 비율로 확대·축소하며 머리만 줄이지 않는다.
- 적의 위협감은 키 비율을 바꾸는 대신 표정, 흉터, 체격의 폭, 갑옷·의상, 무기, 자세로 표현한다. 적도 귀여운 SD 실루엣을 유지하되 성격과 역할은 구분되게 한다.
- 주인공과 적의 선 굵기·윤곽 처리·명암 단계·채색 밀도·색감·얼굴 표현을 동일한 페인터리 무협 스타일로 맞춘다. 한쪽만 도트화하거나, 사실적 성인 일러스트·다른 렌더링 기법으로 바꾸지 않는다. 승인된 주인공 대기 이미지와 적 대기 이미지를 나란히 놓고 그림체와 머리/몸 비율을 먼저 검수한다.
- 주인공만 전투 화면 왼쪽에서 오른쪽을 바라본다. 모든 적은 화면 오른쪽에서 왼쪽을 바라본다. 적을 좌우 반전해 방향 오류를 숨기지 않는다.
- 프레임 내부에서도 주인공의 캐릭터 중심축은 왼쪽, 적의 중심축은 오른쪽에 고정한다. 주인공은 오른쪽 공격 공간을, 적은 왼쪽 공격 공간을 확보한다. 이는 단순히 그림의 왼쪽/오른쪽 끝을 맞추는 정렬이 아니라 캐릭터의 고정 루트 기준점을 맞추는 정렬이다.
- 생성 목록, 프레임 수, 최종 셀 크기, 기준점, 기준 신체 크기를 먼저 확정한다. 수치를 프롬프트와 납품 메타데이터에 동일하게 기록한다.

### 현재 캐릭터 세트

| 캐릭터 | idle | attack1 | attack2 | death |
| --- | ---: | ---: | ---: | ---: |
| 목현 / 혈랑채 두목 | 6 | 9 | 9 | 8 |
| 혈랑채 졸병 / 궁수 / 정예산적 | 6 | 9 | 9 | 8 |

총 20장·160프레임이다. 공격은 준비·가속·타격·회수·복귀를, 사망은 균형 붕괴·무기 낙하·착지·홀드를 각각 구분한다. 다른 캐릭터는 별도 기획에 따라 확정한다.

## 3. 신규 최종 시트 제작 기준

| 항목 | 기본 목표 |
| --- | --- |
| 한 프레임 | 512×512px 고정 셀 |
| 시트 | 4열, 6~8프레임은 2행·9프레임은 3행 |
| 순서 | 좌→우, 위→아래, 남는 셀은 완전 투명 |
| 셀 사이 이동량 | x/y 각각 512px |
| 안전 여백 | 캐릭터·무기·궤적 모두 셀 네 변에서 최소 32px |
| 인접 콘텐츠 간 최소 간격 | 양쪽 여백 합 64px |
| 주인공 기준점 | 기본 목표 (128,448) = (W×0.25,H×0.875), 프레임 왼쪽 중심축 |
| 적 기준점 | 기본 목표 (384,448) = (W×0.75,H×0.875), 프레임 오른쪽 중심축 |
| 기준 신체 높이 | 캐릭터별 대기 자세 약 256px를 출발점으로 확정·기록 |
| 형식 | 실제 알파 채널이 있는 RGBA PNG |

### 3.1 실제 전투 화면 기준의 원본 크기

현재 전투 캔버스는 640×390px 논리 해상도이고, 한 캐릭터의 목표 표시 높이는 약 256px이다. PixiJS는 이 캔버스를 기기 픽셀 배율에 맞춰 **최대 2배(1280×780px)**로 렌더링한다(`resolution: min(devicePixelRatio, 2)`). 따라서 런타임 텍스처가 화면에 실제로 쓰이는 최대 해상도는 **표시 크기의 2배**이고, 그보다 큰 픽셀은 화면에 도달하지 못하는 다운로드·GPU 메모리 낭비다. 원본 후보의 큰 작업 캔버스는 허용하지만, 런타임에 쓰는 최종 PNG/JSON은 아래 범위로 줄여 패킹한다.

| 항목 | 신규 제작 기본(1배) | 해상도 상한(2배) |
| --- | --- | --- |
| 대기 신체 높이 | 약 256px | 약 512px |
| 한 프레임 | 512×512px 공통 셀 | 표시 셀 크기×2 (256px 표시 기준 약 920px) |
| 6~8프레임 시트 | 2048×1024px (4열×2행) 또는 3.2 트림 패킹 | 3.2 트림 패킹 |
| 9프레임 시트 | 2048×1536px (4열×3행) 또는 3.2 트림 패킹 | 3.2 트림 패킹 |

- 런타임 셀 크기는 `표시 셀 크기(논리 px) × 2`를 넘지 않는다. 기존 시트를 줄일 때는 `새 셀 = 원본 셀 × 표시 배율 × 2`로 계산하고, 표시 배율은 `원본 표시 배율 × 원본 셀 ÷ 새 셀`로 바꿔 화면 크기를 유지한다.
- 512px 셀은 배율 1 기기에서 1:1이고, 배율 2 이상 기기에서는 약 2배 확대되어 조금 부드럽게 보인다. 모바일 다운로드·메모리를 줄이는 기본값으로 쓰고, 고배율 기기에서 선명도가 필요한 캐릭터만 2배 상한까지 올린다.
- 상한을 넘는 1024px 셀·4096px 폭 시트는 런타임에 쓰지 않는다.
- 공격 범위가 부족하면 먼저 무기 궤적과 포즈의 폭을 규격 안에서 조정한다. 실제로 잘리는 경우에만 최대 점유 범위와 목표 표시 크기를 실측해 이 문서와 JSON 규격을 함께 갱신한다. 단순히 원화가 크거나 확대 검수가 편하다는 이유로 셀 크기를 키우지 않는다.

목현 v2 런타임 시트는 2배 상한 규격이다. 920×920px 셀(대기 신체 높이 약 527px)을 `PLAYER_SCALE` 0.5로 표시하며, 루트는 (269.5, 805)px·정규화 anchor는 (0.29297, 0.875)다. 3.2 트림 패킹으로 대기 877×1072px, 공격1 1583×1495px, 공격2 1539×1504px, 사망 1408×1515px 시트를 쓴다.

프레임 크기는 대기 포즈가 아니라 **4모션 전체에서 발생하는 최대 공격 범위와 모든 자세의 점유 영역**을 기준으로 정한다. 몸·무기·참격 궤적·머리카락·뒤로 젖힘·쓰러짐까지 고정 루트 기준의 합집합으로 측정하고 네 변의 안전 여백을 더한다. 함께 제작하는 주인공·적 세트의 모든 모션과 모든 프레임에 동일한 W×H를 사용한다. 512×512는 기본 목표이지 잘림을 허용하는 상한이 아니다.

512px에 이 영역이 들어가지 않으면 생성 전에 공통 셀을 확대하고 해당 제작 세트 전체의 시트 크기·기준점·메타데이터를 함께 갱신한다. 특정 모션만 큰 프레임으로 만들거나 특정 프레임만 축소해 억지로 넣지 않는다. 대기에도 공격과 동일한 빈 공간을 유지한다. 제작·검수 단계에서 프레임별 크롭으로 여백을 없애지 않는다. 런타임 용량을 줄이는 트림은 3.2의 복원 데이터를 남길 때만 허용한다. 이미 구현된 셀 규격을 유지해야 하는 작업은 해당 규격을 명시적으로 채택하고 이유를 남긴다.

가로 25%/75%는 좌우 배치를 구체화한 기본 목표다. 후방 머리카락·검집과 전방 공격 범위가 모두 들어가는지 실측해 제작 전에 최종 비율을 확정한다. 확정한 역할별 중심축과 지면 기준은 대기/공격1/공격2/사망 전부에서 바꾸지 않는다. 무기·궤적을 포함한 전체 바운딩 박스의 중앙이나 매 프레임 발의 최하단으로 기준점을 다시 계산하지 않는다. 몸통의 기울기·발걸음·쓰러짐은 같은 루트에 대한 의도된 자세 변화로 표현한다.

**파일 크기가 같다고 캐릭터 크기가 같은 것은 아니다.** 같은 캐릭터는 모든 모션에서 머리·몸통 기준 배율을 유지한다. 무기나 궤적까지 포함한 바운딩 박스를 같은 높이로 맞추지 않는다. 웅크림·쓰러짐에서 실제 차지하는 높이가 줄어드는 것은 정상이다. 포즈가 바뀌어도 월드 기준점이 이동하지 않아야 한다.

### 3.2 트림 패킹과 프레임별 기준점

2D 게임은 크기가 제각각인 프레임을 쓰면서도 캐릭터가 흔들리지 않는다. 프레임마다 "캐릭터 위치에서 어디에 그릴지"라는 오프셋을 별도 데이터로 가지기 때문이다. 고정 셀 방식은 이 오프셋을 그림의 셀 안 위치로 미리 넣어 둔 것이며, 좌표가 맞으면 화면 결과는 두 방식이 같다.

| 항목 | 고정 셀 격자 | 트림 패킹 + 프레임별 복원 좌표 |
| --- | --- | --- |
| 기준점 | 셀 안 같은 좌표에 그림을 배치, 시트당 anchor 하나 | JSON이 프레임별 원래 셀 크기와 잘린 위치를 기록 |
| 검수 | 편집기에서 겹쳐 보기로 바로 확인 | 좌표 오류가 눈에 잘 띄지 않아 복원 검사 필수 |
| 텍스처 | 빈 여백이 많고, 가장 넓은 공격이 셀 크기를 결정 | 여백을 잘라 작다 |

**제작·검수는 고정 셀로 하고, 런타임 납품만 트림 패킹을 선택한다.**

1. 그림은 3장의 공통 셀·루트 기준으로 만들고 고정 셀 상태에서 GIF·기준점 검수를 마친다.
2. Aseprite `ExportSpriteSheet`로 내보낸다: `type=PACKED`, `trim=true`(프레임마다 여백 제거), `shapePadding=2`, `borderPadding=1`. 선형 필터로 축소 표시할 때 이웃 프레임 색이 번지지 않도록 간격을 둔다.
3. 프레임 JSON에 `frame`(시트 안 잘린 영역), `spriteSourceSize`(원래 셀 안 위치), `sourceSize`(원래 셀 크기)를 남긴다. `meta.anchor`는 원래 셀 기준 정규화 값이다. 한 Aseprite 파일의 여러 태그를 모션별 시트로 나눠 내보내면 `frameTags`의 `from/to`가 전체 인덱스로 들어가므로, 시트 안 0부터 시작하는 값으로 고친다.
4. 로더(`src/canvas/sprite.ts`)는 `sourceSize`·`spriteSourceSize`가 있으면 PixiJS `Texture`의 `orig`(원래 셀)·`trim`(잘린 위치)으로 프레임을 복원한다. 두 값이 없는 시트는 고정 격자로 읽는다. 복원된 스프라이트의 크기·anchor는 원래 셀 기준이라 표시 배율과 위치 계산이 고정 셀 시트와 같다.
5. 모든 프레임을 JSON 좌표대로 빈 셀에 붙였을 때 고정 셀 원본과 픽셀 단위로 같아야 한다. 이후 실제 게임에서 대기·공격·사망 전환 중 발 위치가 튀지 않는지 확인한다.
6. 투명 가장자리가 있는 원화를 줄일 때는 premultiplied alpha(예: Pillow `RGBa`)로 리사이즈해 외곽에 어두운 테두리가 생기지 않게 한다.

**기준점 계산.** 기준점은 발이 닿는 지면 y와 몸통 중심 x다. 몸통 중심은 무기·궤적·이펙트를 뺀 몸통의 무게중심이나 두 발 사이 중앙으로 구한다. 무기까지 포함한 바운딩 박스 중앙에 맞추면 팔을 뻗거나 칼을 휘두를 때 박스가 넓어져 캐릭터가 좌우로 흔들린다.

**게임에서 추출한 기존 시트를 분석할 때.** 게임 화면에서 추출해 늘어놓은 시트(예: 메탈슬러그 추출 시트)는 프레임별 오프셋과 동작 순서 데이터가 빠진 채 눈대중으로 정렬된 자료다. 균등 격자로 자르거나 박스 중앙에 맞추면 흔들리므로 다음 순서로 복원한다.

1. 가장자리와 이어진 배경색만 제거한다. 검정 배경이면 캐릭터 안쪽의 검은 외곽선을 지우지 않는다.
2. 연결된 픽셀 덩어리로 프레임 박스를 구한다. 떨어진 조각(총알·불꽃·먼지)은 가까운 프레임에 합치고, 이웃과 붙은 폭발처럼 크기가 비정상인 덩어리는 수동으로 나눈다.
3. 크기·색·실루엣으로 동작 묶음과 순서를 추정하고 사람이 확인한다.
4. 발 지면 y와 몸통 중심 x로 기준점을 계산하고, 이전 프레임과 머리·몸통을 겹쳐 가장 잘 맞는 위치로 보정한다. 발이 보이지 않는 폭발·사망 프레임은 앞 프레임 기준점을 이어받거나 수동으로 지정한다.
5. 고정 셀로 재패킹하고 정상·저속 GIF로 흔들림을 검수한다.

상용 게임에서 추출한 스프라이트는 저작권 대상이다. 기술 분석·참고용으로만 쓰고 게임 에셋에 넣지 않는다.

### 3.3 도트 스프라이트로 제작할 때

- 그림체 통일 원칙에 따라 주인공만 도트로 바꾸지 않는다. 도트를 채택하면 같은 전투 세트의 모든 캐릭터를 함께 전환한다.
- PixiJS 기본 선형 필터는 확대한 도트를 흐리게 만든다. 도트 텍스처에만 `texture.source.scaleMode = 'nearest'`를 적용하고, 축소 표시하는 페인터리 시트에는 적용하지 않는다.
- 표시 배율은 2·3·4 같은 정수배로 맞춘다. 소수 배율은 화면의 픽셀 크기가 들쭉날쭉해진다.
- 알파는 0/255만 쓰고, 한 캐릭터의 모든 모션이 같은 팔레트를 공유한다.
- 페인터리 원화를 축소·감색해 만든 도트는 얼굴과 외곽선이 뭉개진다. 최종 품질이 필요하면 도트 기준 이미지를 따로 제작한다.
- 도트 생성 도구의 캔버스 크기(예: 64×64)는 캐릭터 키가 아니다. 결과의 실제 신체 높이를 재서 표시 배율을 정한다.

## 4. 모션 품질

- 대기: 시작과 끝이 자연스럽게 이어진다. 호흡 때문에 신체 전체가 확대·축소되지 않는다.
- 공격: 준비→공격→회복이 연결된다. 무기를 쥔 손과 손잡이 접점이 유지되고 칼날 길이가 변하지 않는다.
- 공격 궤적: 실제 무기 이동 방향에 맞는 효과를 포함한다. 이웃 프레임 침범, 무기와 분리된 엉뚱한 궤적, 과도한 광원 배경은 금지한다.
- 사망: 특히 1~3프레임의 무기 위치를 연속으로 검수한다. 잡기→놓기→낙하→착지 과정에서 칼이 사라지거나 순간적으로 뒤집히면 실패다. 마지막 프레임은 쓰러진 자세로 홀드할 수 있어야 한다.
- 칼날에 붕대·천·장식 끈을 추가하지 않는다. 손잡이의 감개와 칼날을 구분한다.
- 모션 연결: 대기→공격 준비→공격 정점→회복→대기가 자연스럽게 이어져야 한다. 사망 진입도 같은 축·신체 배율로 연결한다. 접속 프레임의 몸통·발·손·무기 위치를 비교해 크롭 오차로 인한 순간이동이 없는지 검수한다. 사망을 억지로 대기로 되돌려 루프시키지 않는다.

### 4.1 프레임별 고유 동작

프레임 수는 파일 개수가 아니라 **눈으로 구분되는 동작 단계의 수**다. 같은 그림을 복제하거나 거의 보이지 않는 수치만 바꿔 프레임 수를 채우지 않는다.

- 모든 프레임은 `대기`, `준비`, `가속`, `타격 직전`, `타격`, `후속`, `복귀`처럼 한 문장으로 설명할 수 있는 역할을 가진다.
- 연속된 두 프레임은 몸통 각도, 팔꿈치·손목·무릎 위치, 무기 각도·끝점, 무게 중심, 머리카락·옷자락 후속 동작 가운데 최소 두 항목이 달라야 한다.
- 캐릭터 전체의 단순 이동, 동일 비율 확대·축소, 미세한 회전, 픽셀 해시 차이만으로는 새 동작 프레임으로 인정하지 않는다. 루트 고정 기울기나 웅크림은 관절·무기 변화에 더하는 보조 수단으로만 사용한다.
- 앞뒤 키포즈를 그대로 한 장씩 더 넣지 않는다. 중간 프레임의 무기 끝점과 손 위치는 시간 순서상 두 키포즈 사이에 있어야 한다.
- 원본 시트에서 기존 포즈를 수정해 중간 프레임을 만들 때도 얼굴·의상·무기 형태는 고정하되, 팔·다리·몸통·무기의 실루엣은 실제로 다시 구성한다.
- PNG 바이트나 해시가 서로 다른지는 중복 파일을 찾는 기계 검사일 뿐이다. 최종 판정은 실제 게임 배율과 GIF에서 사람이 동작 차이를 식별할 수 있는지로 한다.

### 4.2 9프레임 공격 구성

| 프레임 | 역할 | 반드시 보이는 변화 |
|---:|---|---|
| 1 | 대기 연결 | 기본 자세와 동일한 시작점 |
| 2 | 준비 | 무게 중심 이동, 무릎 굽힘, 검을 드는 손의 이동 |
| 3 | 최대 준비 | 검과 팔이 공격 반대 방향으로 가장 멀리 이동 |
| 4 | 가속 | 몸통이 공격 방향으로 전환되고 검 끝점이 3·5번 사이에 위치 |
| 5 | 타격 직전 | 전진 자세와 손목 회전이 명확함 |
| 6 | 타격 정점 | 최대 공격 범위와 가장 강한 궤적 |
| 7 | 후속 동작 | 타격 방향을 지나간 검·팔·옷자락의 관성 |
| 8 | 복귀 | 검과 팔이 대기 위치로 돌아오는 중간 자세 |
| 9 | 대기 복귀 | 1번과 자연스럽게 연결되는 종료점 |

1번과 9번은 루프 접속을 위해 같을 수 있다. 그 밖의 프레임은 서로 다른 동작이어야 한다. 특히 2·4·8번은 인접 키포즈를 복제하지 않고 준비·가속·복귀를 각각 보여줘야 한다.

### 4.3 재생 검수

1. 투명 배경의 프레임 배열을 같은 크기로 나란히 놓고 실루엣과 무기 끝점의 이동을 확인한다.
2. JSON의 실제 duration으로 GIF를 만들고 정상 속도와 2배 느린 속도로 각각 확인한다.
3. 게임의 실제 표시 배율로 축소해 320px 폭 화면에서 준비·타격·복귀가 구분되는지 확인한다.
4. 동일 프레임 해시, 거의 같은 알파 실루엣, 한 프레임만 튀는 크기·루트 이동을 자동 검사한다.
5. 기계 검사를 통과해도 정상 속도에서 정지하거나 두 번 반복해 보이는 구간이 있으면 해당 중간 프레임을 다시 만든다.

## 5. 투명 배경 처리

**모든 캐릭터 이미지의 배경은 반드시 제거한다.** 처음부터 투명 배경을 요청하고, 생성 결과에 배경이 남으면 제거와 윤곽선 검수를 마친 뒤에만 최종 시트로 사용한다. 배경이 있는 이미지는 생성 후보일 뿐 완료본이 아니다. 체크무늬·검정·흰색을 그려 넣은 RGB 이미지는 투명 이미지가 아니다. 파일 확장자와 미리보기만으로 통과시키지 않는다.

배경 제거는 원본을 보존한 별도 출력으로 수행한다. 배경 제거 단계에서는 캐릭터를 재배치·리사이즈·재디자인하지 않는다. 생성 도구가 외형이나 배치를 바꾸면 해당 결과는 폐기한다. 대체 처리 방식은 사용자의 승인과 사용 도구의 규칙을 따른다.

회색/흰색 전체 삭제를 금지한다. 칼날·흰 의상·활시위·효과 중심부까지 지워질 수 있다. 외곽선 보호와 영역별 검수를 수행한다. **알파 채널 존재는 필요조건일 뿐, 배경 제거 품질의 증거가 아니다.** 반투명 궤적 안에 체크무늬가 남았는지, 흰 효과가 뚫렸는지, 가장자리에 밝은 테두리가 남았는지도 확인한다.

## 6. 생성과 패킹을 분리한다

1. 기준 외형을 고정하고 우선 대기·가장 넓은 공격·사망을 시험 제작한다.
2. 외형·방향·연속성·투명도를 검수한 뒤 나머지 모션을 생성한다.
3. 생성 도구가 정확한 격자를 지켰다고 가정하지 않는다. 원본은 후보 자료로 보관한다.
4. 프레임끼리 겹쳤다면 해당 포즈를 독립 이미지로 재생성한다. 이미 겹친 그림은 사각형 좌표만 바꿔 분리할 수 없다.
5. 프레임별 소유 영역을 확인하고 동일 신체 배율·기준점으로 고정 셀에 패킹한다. 복원 좌표 없이 프레임을 내용에 맞게 잘라 서로 다른 크기로 납품하지 않는다. 런타임 트림은 고정 셀 검수를 마친 뒤 3.2 방식으로만 내보낸다.
6. 최종 PNG와 JSON을 함께 만든 뒤 실제 게임과 같은 스케일에서 모든 모션을 연속 재생한다.

## 7. 납품과 완료 판정

납품: 원본 후보, 최종 PNG, 프레임 JSON, 사용한 기준 이미지/규격, 검수 결과. PNG/JSON에는 동일한 캐릭터·모션 이름을 사용한다. JSON에는 이미지 크기, frame x/y/w/h, 순서, duration, 기준점, 셀 크기, 여백을 기록한다. 트림 패킹 시트는 프레임마다 `spriteSourceSize`·`sourceSize`를 함께 기록한다. duration은 그림에서 추정해 확정하지 말고 기존 게임 타이밍 또는 별도 승인값을 따른다.

다음 항목을 모두 통과하기 전에는 “게임 적용 가능/완료”로 표시하지 않는다.

- [ ] 고정 격자 시트는 실제 이미지 크기가 선언된 열 수×셀 크기, 행 수×셀 크기와 일치한다. 트림 패킹 시트는 모든 프레임을 JSON 좌표로 셀에 복원한 결과가 고정 셀 원본과 픽셀 단위로 일치한다.
- [ ] 런타임 셀이 실제 전투 화면 표시 크기의 2배(256px 표시 기준 약 920px 셀)를 넘지 않으며, 표시 배율을 바꿔 화면 크기를 유지했다.
- [ ] 주인공과 적이 모두 약 2.5등신 SD 비율이며, 적에게 5등신 이상의 성인 체형이 섞이지 않았다. 선·명암·채색·얼굴 표현을 나란히 비교해 같은 그림체임을 확인했다.
- [ ] 모든 프레임 수·방향·순서가 맞고 이웃 포즈가 섞이지 않는다.
- [ ] 시작·종료 접속 프레임을 제외한 모든 프레임이 서로 다른 역할과 실루엣을 가지며, 인접 프레임의 몸통·관절·무기 변화 중 최소 두 항목이 눈으로 구분된다.
- [ ] 공격 2·4·8번 프레임이 각각 준비·가속·복귀를 표현하며 인접 키포즈의 복제나 단순 전체 변형이 아니다.
- [ ] 공격 범위를 포함해 제작 세트의 모든 모션/프레임 셀 크기가 같고 안전 여백 32px가 완전히 투명하다.
- [ ] 주인공 왼쪽 축·적 오른쪽 축이 각자의 모든 모션에서 고정되며, 공격하지 않는 포즈에도 같은 공격 공간을 남겼다.
- [ ] 모든 캐릭터 PNG에서 배경이 제거됐고 실제 알파가 0인 영역이 있으며, 빈 셀과 프레임 사이에 배경 픽셀이 없다.
- [ ] 어두운색·밝은색·유채색 배경에 합성해 체크무늬, 구멍, 테두리 잔상을 검사했다.
- [ ] 무기·의상·활시위·공격 궤적을 원본과 확대 비교했다.
- [ ] 대기↔공격↔사망 전환에서 머리·몸통 배율과 기준점이 튀지 않는다.
- [ ] 실제 로더의 anchor와 납품 기준점이 일치한다.

공통 셀 W×H에서 frame i는 x=(i%4)×W, y=floor(i/4)×H, w=W, h=H다. 기본 정규화 anchor는 주인공 (0.25,0.875), 적 (0.75,0.875)이며 최종 확정값을 JSON에 역할별로 기록한다. 월드 좌표에는 이 루트 기준점을 연결한다. 셀 크기나 로더의 anchor만 바꾸지 말고 실제 그림의 기준점과 함께 일치시켜야 한다. 트림 패킹 시트의 frame 좌표는 이 격자 공식을 따르지 않으며, `spriteSourceSize`·`sourceSize`로 같은 공통 셀에 복원한다. 목현 v2의 런타임 셀과 루트는 3.1에 기록한다.

상태는 **생성 후보 → 투명화 검수 → 패킹 검수 → 게임 적용 검수**로 구분한다. 단순 파일 확보와 게임 적용을 혼용하지 않는다. 공통 재사용 프롬프트는 이 지침에 보존하고 개별 생성 큐의 완료된 일회성 프롬프트는 큐 정책을 따른다.

## 8. 재사용 생성 프롬프트

```text
게임용 페인터리 무협 캐릭터 모션 시트 제작.
기준 이미지: [승인된 대기 포즈]. 캐릭터: [이름]. 모션: [모션]. 프레임: [N]개.
기준 이미지의 얼굴, 머리와 몸 비율, 의상, 색, 무기 길이를 모든 프레임에서 유지.
주인공과 적 모두 머리부터 발끝까지 약 2.5등신의 귀여운 SD 비율. 적도 5등신 이상의 사실적 성인 체형 금지.
적의 위협감은 표정·흉터·넓은 체격·갑옷·무기·자세로 표현하되 주인공과 선 굵기·명암·채색 밀도·얼굴 표현을 통일.
방향: [주인공: 오른쪽 / 적: 왼쪽]. 방향 변경이나 좌우 반전 금지.
최종 목표 [4W]×[ceil(N/4)×H]px, 4열×[ceil(N/4)]행, 각 셀 [W]×[H]px.
현재 640×390px 전투 화면에서 캐릭터 표시 높이는 약 256px이다. 신규 최종 셀은 512×512px을 사용하고, 1024px 셀이나 4096px 폭 시트를 만들지 말 것.
W/H는 4모션 전체의 최대 공격 범위와 쓰러짐까지 포함해 여백을 더한 공통 크기다.
대기/공격1/공격2/사망 모든 프레임에 같은 셀 크기를 사용한다.
왼쪽부터 순서대로 채우고 남는 셀은 완전히 투명하게 비워 둔다.
캐릭터 루트 중심축: 주인공은 프레임 왼쪽 [기본 W×0.25], 적은 오른쪽 [기본 W×0.75].
지면 기준 y=[기본 H×0.875]. 확정한 x/y를 모든 모션에서 동일하게 유지한다.
주인공은 오른쪽에, 적은 왼쪽에 무기와 공격 궤적의 전체 공간을 확보한다.
무기 포함 그림 전체의 가운데로 캐릭터를 재정렬하지 않는다.
대기 기준 신체 높이 [확정값]px와 같은 신체 배율을 모든 모션에서 유지한다.
캐릭터, 무기, 머리카락, 공격 궤적 모두 셀 경계에서 최소 32px 안쪽에 둔다.
이웃 프레임과 겹침, 잘림, 프레임별 자동 줌, 포즈별 크기 변경 금지.
시작·종료 접속 프레임 외에는 동일하거나 거의 같은 포즈 금지. 각 프레임에 동작 역할을 부여할 것.
연속 프레임마다 몸통·관절·무기·무게 중심·옷자락 중 최소 두 항목이 달라질 것.
9프레임 공격의 2번은 준비, 4번은 가속, 8번은 복귀 자세이며 인접 키포즈를 복제하지 말 것.
공격은 무기 이동과 일치하는 궤적 포함. 사망은 무기 놓기와 낙하가 연속적으로 연결.
대기→공격→회복→대기 및 사망 전환에서 중심축·배율·손과 무기 위치가 자연스럽게 이어질 것.
칼날에 천이나 붕대 금지. 배경, 바닥 그림, 체크무늬, 번호, 라벨, 테두리, 워터마크 금지.
모든 캐릭터 이미지의 배경을 반드시 제거하고 실제 투명 알파 채널을 가진 PNG로 납품.
배경이 투명해 보이는 체크무늬 그림으로 대체하지 말 것. 배경이 남으면 완료본이 아님.
```

위 수치는 요청 목표다. 생성 결과가 이를 지켰는지는 별도 실측한다. 지키지 못한 후보를 균등 분할 가능한 완성본이라고 설명하지 않는다.

## 9. 기존 재생성본에 대한 주의

2026-09-12의 `output/sprite-regeneration/transparent/` 27장은 1774×887px이다. 4×2 명목 격자는 평균 443.5px이며, 이번 기본 목표와 다르다. 투명화 때 위치·크기를 바꾸지 않았으므로 일정한 간격·신체 배율로 패킹 완료된 자료가 아니다.
