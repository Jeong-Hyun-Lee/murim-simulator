# 신규 투명 모션 시트 구현 참고 명세

## 적용 범위와 상태

대상: `transparent/`의 주인공·혈랑채 보스·졸병·궁수·정예산적 모션 시트 27장.

**배경 제거만 완료된 원본 크기의 이미지다. 동일한 프레임 간격·신체 크기로 패킹된 런타임 시트가 아니다.** 이전 배경 제거 작업에서는 픽셀을 이동하거나 크기를 변경하지 않았다. 이번 문서는 측정 및 구현 참고용이며 게임 이미지나 재생 코드를 변경하지 않는다.

## 프레임별 크기와 여백 데이터

`layout-measurements.json`에 27장 각각의 명목 프레임 측정값을 기록했다.

- `nominalRect`: 시트 내 명목 셀의 x/y/w/h.
- `alphaBoundsWithinNominalCell`: 해당 셀 안 알파 영역의 [left, top, right, bottom]. 셀 기준 좌표이며 오른쪽/아래는 미포함.
- `contentSizeWithinNominalCell`: 해당 영역의 너비/높이. **무기·궤적을 포함하며 신체 크기가 아니다.**
- `transparentMarginsWithinNominalCell`: 좌/상/우/하 투명 여백.
- `opaquePixelsOnCellEdge`: 명목 셀 가장자리의 알파 양수 픽셀 수(모서리 중복 집계).
- `safeForUniformSlicing: false`: 아직 게임용 균등 분할을 승인하지 않은 상태.

인접 셀의 오른쪽/왼쪽 여백 합은 명목 격자 내 수평 투명 띠를 참고할 때만 쓴다. 프레임 소유권이 확정되지 않은 상태이므로 실제 포즈 사이의 정확한 거리로 간주하지 않는다. 이 JSON을 런타임 프레임 메타데이터 대신 로드하면 안 된다.

## 권장 최종 패킹 규격 — 아직 미적용

좌표 이동만으로 안전하게 재생하려면 아래 규격으로 포즈를 추출·정렬한 최종본을 별도 제작한다.

| 항목                   | 권장값                                                 |
| ---------------------- | ------------------------------------------------------ |
| 프레임 셀              | 512 × 512px                                            |
| 시트                   | 4열 × 2행 = 2048 × 1024px                              |
| 셀 이동량              | 가로 512px, 세로 512px                                 |
| 안전 여백              | 무기·궤적 포함 네 변 최소 32px                         |
| 셀 간 콘텐츠 최소 분리 | 양쪽 안전 여백 합 64px                                 |
| 서 있는 포즈 기준점    | 셀 내부 (256,448), 발바닥 기준                         |
| 권장 기준 신체 높이    | 캐릭터별 대기 포즈를 기준으로 약 256px, 무기/궤적 제외 |
| 빈 셀                  | 완전 투명                                              |
| 트리밍/회전            | 금지, 모든 프레임 전체 셀 크기 유지                    |

공격/웅크림/사망은 포즈 때문에 바운딩 박스 높이가 달라지는 것이 정상이다. 각 프레임의 전체 바운딩 박스를 같은 높이로 맞추면 다시 크기가 튄다. **머리·몸통 비율로 같은 캐릭터의 배율을 유지**하고 사망도 같은 월드 기준점을 보존한다. 무기나 궤적이 448px 안전 영역에 안 들어오면 해당 프레임만 축소하지 말고 전체 셀 규격을 늘리거나 모든 관련 모션에 같은 배율을 적용한다.

최종 패킹이 이 규격을 충족한 후에만 0-based 프레임 i에 대해 다음 좌표를 사용한다:

```text
x = (i % 4) * 512
y = floor(i / 4) * 512
w = h = 512
anchor = (0.5, 0.875)  // (256,448)를 월드 위치에 고정
```

현재 `src/canvas/sprite.ts`의 `loadAnimatedSprite`는 JSON의 x/y/w/h로 자르고 `anchor=(0.5,1)`을 사용한다. 위 권장 패킹을 채택할 때는 발 기준을 위해 anchor를 (0.5,0.875)로 맞추거나 동일한 64px 보정값을 일관되게 적용해야 한다. 현재 후보 PNG에 이 공식을 바로 적용하지 않는다. 프레임 재생 시간은 이번 이미지 측정으로 결정할 수 없으므로 기존 모션 타이밍과 별도로 검증한다.
