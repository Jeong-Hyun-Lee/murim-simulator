# 캐릭터 모션 재생성 — 검수 중

## 요청과 완료 기준

캐릭터별 모든 모션에서 신체 크기를 유지하고, 각 프레임의 캐릭터·무기·궤적이 이웃 프레임과 겹치지 않아야 한다. 동일한 셀 크기와 기준점으로 좌표를 지정해 재생할 수 있어야 한다. 주인공은 오른쪽, 적은 왼쪽 응시를 유지한다.

## 현재 산출물

- `IMPLEMENTATION-SPEC.md`: 실제 크기·명목 셀 좌표·간격 제한·미적용 권장 패킹 규격.
- `layout-measurements.json`: 27장 명목 프레임별 영역 크기·좌우상하 여백·경계 검출. 런타임 아틀라스가 아닌 진단용 데이터.
- `sources/`: 내장 이미지 생성 도구로 새로 생성한 27개 후보 시트.
- `transparent/`: 원본 크기·좌표·RGB를 유지하고 배경 알파를 제거한 PNG 27개. 이미 투명했던 4개는 그대로 복사한다.
- `transparency-report.json`: 파일별 배경 제거 비율 및 원본 RGB/크기 보존 검사.
- `*-comparison.jpg`: 왼쪽은 단색 배경에 합성한 투명본, 오른쪽은 원본인 검수용 이미지. JPG는 게임용 에셋이 아니다.
- `manifest.json`: 캐릭터·모션·프레임 수·생성 원본 경로.
- 후보는 최종 런타임 에셋이 아니다. 기존 게임 에셋에는 적용하지 않았다.

## 검수 결과와 남은 작업

4열×2행 격자를 요청해 프레임 사이 공간을 확보했다. 그러나 생성 도구가 정확한 셀 경계·모션 간 신체 배율·기준점을 일관되게 지키지 못했다. 일부 무기/쓰러짐 포즈는 명목상 셀 경계를 넘는다. 프레임을 단순 균등 분할하면 안 된다.

최초 후보 파일 검사: 27장 중 4장만 RGBA, 23장은 체크무늬 또는 검은 배경을 포함한 RGB다. 배경 추출 재요청도 일부 실패했다. 배경, 여백, 비율, 기준점, 실제 재생 검증을 통과하기 전에는 완료로 표시하지 않는다.

사용자 승인으로 이미지 재생성 대신 `remove_background.py`에서 픽셀 기반 배경 제거를 수행했다. 체크무늬의 무채색 영역을 외부부터 채우고, 외곽선 틈을 닫아 흰 의상과 금속 내부를 보호한다. 닫힌 체크무늬 공간은 별도 탐지한다. 원본 픽셀을 이동·확대·축소하지 않는다. 원본 후보와 기존 게임 에셋은 변경하지 않는다. 이번 투명화는 모션 간 배율·격자 정렬 및 런타임 적용이 완료됐다는 의미가 아니다.

## 공통 생성 프롬프트

기존 캐릭터 대기 시트를 외형 참조로 사용. 동일한 얼굴·의상·무기·머리와 몸 비율을 보존. 각 모션의 프레임 수는 idle 6, attack1/attack2 7, hurt 3, death 6, victory 5(주인공/보스만). 2:1 캔버스에 4열×2행의 정사각형 셀을 배치하고 순서대로 채우며 남은 셀은 빈칸. 신체 높이는 셀의 절반, 발 기준점은 셀 높이의 약 80~85%. 무기·궤적을 포함한 모든 픽셀을 셀 내부에 유지하고 큰 투명 여백 확보. 주인공 오른쪽/적 왼쪽 응시. 실제 투명 알파, 텍스트·격자선·체크무늬 배경·이웃 포즈 겹침 금지.

## 재개 시 처리 순서

1. 후보의 실제 배경 제거 후 의상·칼날·궤적 보존 여부 확인.
2. 이웃 그림이 섞이지 않는 프레임별 추출 영역 확정.
3. 무기 포함 바운딩 박스가 아닌 신체/머리 기준으로 배율 보정.
4. 고정 셀에 공통 기준점으로 배치하고 PNG/JSON 함께 생성.
5. 모든 모션 전환을 실제 재생해 크기 튐·잘림·위치 튐 검증 후 교체.
